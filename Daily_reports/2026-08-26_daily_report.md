## 3. 失敗原因診断

### 3.1 箱なし誤候補

誤候補は人物や室内物体ではなく、前側魚眼下部の黒いゴムマットと灰色床の境界だった。
MJPGの閾値近傍画素が青系として残り、形態学的close後に横長輪郭となっていた。

| 指標 | 箱なし誤候補 | 安定した青箱 |
|---|---:|---:|
| 観測数 | 1,240 | 14,002 |
| 幅÷高さ範囲 | 1.545～5.800 | 0.565～1.393 |
| `幅÷高さ <= 1.5` | 0/1,240 | 14,002/14,002 |

面積範囲は重なるが縦横比では分離できたため、HSV閾値変更ではなく最大縦横比1.5を第一候補とした。

### 3.2 FPS

欠番や秒単位停止ではなく、フレーム処理が33.3 ms予算を数msずつ継続超過したことが原因だった。
診断段階では3本のMJPG同期保存が大きな候補だったため、実機で区間別時間を測れるよう計測を追加した。

## 4. 開発実装

### 4.1 横長輪郭除外

`detect_blue_ground_contact`の最大候補選択前に、設定可能な
`blue_ground_contact_max_aspect_ratio`を追加した。設定が存在しない場合は従来動作を維持する。
開発用configだけを1.5とし、本番configには追加していない。

診断録画の再処理では、箱なし2環境を0/818、0/853へ抑え、静止青箱4試行と遮蔽試行の5/5が
ゲート回帰を合格した。

### 4.2 処理時間計測

録画CSVへODOM poll、camera read、BEV、青検出、AI、overlay、display、3動画write、合計の9区間を
`time.perf_counter`で記録するようにした。過去CSVとの互換性を維持したまま、
`diagnose_recording_timing.py`で各区間中央値と有効処理時間を集計できる。

## 6. 実験ランチャー

`src/run_field_experiment.py`を追加した。次の1コマンドで、preflightがPASSした場合だけ
`bird_eye.py`を起動する。

```bash
python3 src/run_field_experiment.py \
  --record-dir recordings/2026-08-27 \
  --experiment-label pilot_odom
```

既定で開発用raw距離config、device 0、1280x720、30 fps、`/odom`、clean Git、単体テストを使用する。
`--dry-run`では機材にアクセスせず2つの実行予定コマンドを確認できる。preflight失敗時はアプリを
起動しないため、ODOMやconfigの指定漏れを本録画前に止められる。
