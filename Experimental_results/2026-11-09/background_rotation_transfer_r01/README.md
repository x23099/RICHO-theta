# 初回の床校正を背景の相対回転で後続画像へ移す診断

続き：[背景検査の通過・保留範囲の監査](../background_transfer_limits_r01/README.md)。合成並進120ケースと実画像追跡点の109除外ケースを追加し、追跡の安定性と距離の正しさを分離した。以下の元結果・コード・閾値は変更していない。

ユーザーの変更指示により引き継ぎ整理を中断し、そのまま研究を再開した。これは実行時機能の変更ではなく、既存10 PNGから得た座標・背景追跡のオフライン検証である。

## 結論

**最初のP0床校正を固定したまま、床マーカーを含まない背景の相対回転を加えることで、今回の後半8画像の条件付き誤差を減らせた。** Eの正解距離や後半の固定4点を補正の推定に使っていない。

ただし、**鏡像仮説は未確認、並進は推定していない、実機精度・live利用・走行／FFBは未承認**。新しい録画や独立した環境での一般化を確認した結果ではない。

## 今回の方法

前段：[外角・背景移動・同一画像4点の比較](../wide_floor_geometry_r01/continuation_report.md)。同じsession `159c37ad534a4ac0b96ca69791713567` のP0=f020063を初期参照とし、f038231以後の8画像へ適用した。P0の2枚の座標が同じだからという理由で試行数を増やさず、初期参照は1枚に限定する。

1. P0の固定A～Dだけで既存KB4→IPPEの床姿勢を求め、両解を固定する。内部校正・高さ・並進は再fitしない。
2. 既に保存した上部背景の追跡点を利用する。画像左レンズの天井／建物領域であり、床のA～D・Eは含まない。[OpenCVのShi–Tomasi](https://docs.opencv.org/4.13.0/d4/d8c/tutorial_py_shi_tomasi.html)と[Lucas–Kanade](https://docs.opencv.org/4.13.0/d4/dee/tutorial_optical_flow.html)による追跡で、画像の見かけの移動を得たもの。物理運動や絶対姿勢を測ったものではない。
3. 参照画像の48px格子の市松状の半分を推定用、残りを検査用へ固定分割する。Eの誤差を見て点や分割を選ばない。
4. 推定用の単位光線だけを用い、SVDで正しい3×3回転 `R_current_from_reference` を求める。
5. 推定に使わなかった背景点を回転させて再投影し、背景の画素残差・点数・広がり・回転量を検査する。距離の正解値で通すゲートではない。
6. 初回の床変換を `T_floor_from_current = T_floor_from_reference × diag(Rᵀ,1)` として更新する。カメラ位置の並進3成分と高さは元の値を厳密に維持する。
7. その画像のEを検証する。後半の固定4点は再投影誤差の比較専用で、更新式やゲートに使わない。

H2の光線x反転仮説では、相対回転も同じ基底へ `S R S`（S=diag(−1,1,1)）で移す。S自体をTFへ渡さず、更新に使う回転の行列式は+1を検査する。**この計算は実際の映像反転を確定・実装するものではない。** 元画像の反転・補正・再保存はしていない。

この方法は、背景6平面で絶対upを初期化する従来scene推定を変更したものではない。**最初の床姿勢が与えられている場合の、後からの小さな向き変化**だけを扱う。

## 並進は背景検査を通ることがある

この方式は回転だけであり、カメラが平行移動しても背景の見かけの変化の一部を回転で説明できる。合成対照として、背景の光学Zを5m、カメラ横移動を5cm、床ターゲットを前方2mとして計算した。

- 推定に使わなかった背景残差中央値約0.222px、90%点約0.436pxで、背景の検査は通過した。
- それでも床ターゲットの位置誤差は約4.25cmあった。
- `translation_estimated=false`、`physical_metric_verified=false`、`usable_for_ffb=false`を維持した。

**背景残差が小さいことは「カメラ中心が動いていない」「床距離が正しい」の証明ではない。** この合成対照は実機で5cm動いたと主張するものではなく、手法の識別不能性を示す。走行でこの補正をそのまま使わない。
