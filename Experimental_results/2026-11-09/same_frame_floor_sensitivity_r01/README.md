# 同一画像の床4点：画素感度と点対応の監査

続き：[L字の辺・小数画素読取りの監査](../wide_l_boundary_audit_r01/README.md)。整数凸頂点、光線平面の辺交点、局所角補正を比べ、補正が入力位置をそのまま返す場合を精密な定位と扱わない検証を追加した。以下の感度計算は変更していない。

## 結論

**広い床4点を使う条件付き推定は維持できるが、2m地点の一致約1.8cmだけで「数cm精度が完成」とは言えない。** 今回の角候補は整数画素であり、仮に1画素ずれると、検証点Eだけでも前方推定が約1.943～2.025mへ変わった。床4点も同時にずらした端点組合せでは約1.893～2.096mだった。

影響が大きいのは、**奥の左右L字の縦画素座標**。Eを固定した試験でも、それぞれの1画素ずれで床位置が最大約2.4cm変わった。近側の横画素より、遠側の外角と検証点をどこで読んでいるかの確認を優先する。

これは未確認のH2（光線x反転）・基準IPPE解0を抜粋した診断であり、反転の実装・採用や精度承認ではない。±0.5／1画素は意図的に与えた試験幅で、実測した不確かさ・信頼区間・連続領域の保証上限ではない。

前段：[同一画像4点での再推定](../wide_floor_geometry_r01/continuation_report.md)、[背景補正の限界](../background_transfer_limits_r01/README.md)。今回、背景追跡・録画間の姿勢転用は使わない。

## 1. 入力と推定・評価の分離

- 同じsession `159c37ad534a4ac0b96ca69791713567` の後半8画像、f038231／038464／043924／044053／051180／051342／054907／055094。
- `corner_identity_r01/corner_identity_comparison.csv` の閾値110・凸角候補を基準とする。人が承認した精密座標ではない。
- 床の固定4点A～Dから、その画像の姿勢だけを推定する。**Eと目標距離は姿勢fitに渡さない。** 高さ59cm・内部校正K/Dもfitしない。
- Eは推定後に床へ交差させる検証点。目標は中央1.40m／2.00m、左右±0.20m・前方1.40m。
- 車体の左右は前進方向を向いた基準と回答済み。画像の左右とは別。マーカー基準は申告どおりL字の**外側の曲がり角**で、内角へ読み替えない。
- 3つの既存仮説・両IPPE解を保持し、元PNGの加工・再出力やruntimeの変更をしない。検証点がL字であり、コーンへの接触距離を新たに実証した試験ではない。

入力PNG・座標CSV・校正・ソースを[SHA来歴](results_r01/input_provenance.json)で照合した。計算スクリプトは[analyze.py](analyze.py)。

## 2. 摂動の種類と件数

|条件|固定4点の座標|検証点E|対象仮説|
|---|---|---|---|
|基準|そのまま|そのまま|H0／H1／H2、両解|
|1座標ずつ|8座標の1つを±0.5／1px、計32組|同じ幅の4端点と基準点|H0／H1／H2、両解|
|4点同時|8座標の±端点全256組×2幅|同じ幅の4端点と基準点|H2のみ、両解|
|Eのみ|基準の姿勢候補を固定|±0.5／1pxの4端点と基準点|H0／H1／H2、両解|

8画像・全条件で**9,872候補評価行**、解不足・例外・未完了0。4点同時の全端点をH2に限定したのは既存の条件付き候補の感度を調べるためで、H2の採用を意味しない。3仮説全ての個別摂動・基準結果も残した。

近い解をEの真値で選ばないため、摂動後の2解を基準の2解へ姿勢だけで対応付けた。回転角差＋並進差／0.8mの合計で2通りの対応を比較し、両解を残す。曖昧時は対応なしとして扱う。今回は曖昧0、solver順と対応枝の入替0だった。

全端点の列挙は独立ノイズの標準偏差を推定する処理ではない。また、非線形推定のため、端点だけを列挙して連続した画素領域内の全ての極値を証明したわけではない。

## 3. 検証点だけのずれと、床4点との同時ずれ

以下は**H2・基準解0**、各配置2画像の範囲。2枚は独立した精度試験ではない。Zは校正時の車体原点からの前方成分であり、水平斜距離や接触距離ではない。

|配置|基準Z|Eだけ±1pxのZ範囲|床4点とEの各座標±1px端点組合せのZ範囲|
|---|---:|---:|---:|
|中央1.40m|1.394m|1.372～1.416m|1.349～1.440m|
|中央2.00m|1.983m|1.943～2.025m|1.893～2.096m|
|車体左、前方1.40m|1.391m|1.368～1.414m|1.346～1.439m|
|車体右、前方1.40m|1.400m|1.378～1.422m|1.355～1.446m|

2m地点では、Eだけ±0.5pxなら1.963～2.004m、床4点とEを±0.5pxの端点へ動かすと1.936～2.036m。基準値の小さな誤差と、画素の読取りへ依存する変動を混同しない。

床4点の同時±1px条件でH2解0の高さは約0.521～0.624mへ変化した。持越しの申告0.590mもこの範囲に入るが、**0.590mに合う角候補を選んだり、申告高さが誤りと断定したりはしない。** 読取り・物理点対応・内部校正の問題を分ける。

H1（固定点左右をEに合わせた対応、生光線）では、基準・個別摂動・Eのみの計560行全てが物理的に不整合で、高さは約−0.5785～−0.3824mだった。負の高さを絶対値化して通していない。±1pxの個別ずれだけで符号問題は解消しなかった。

根拠：[全候補CSV](results_r01/pixel_stress.csv)、[配置・条件別の集計](results_r01/group_metrics.csv)。集計の `min_Z_m/max_Z_m` はEの端点試験も含む。`predicted_X_m/Z_m` は各床姿勢に対して**Eの元座標を固定**した予測なので、次節ではこちらだけを使用する。

## 4. どの床角の読取りを優先するか

[rank_coordinates.py](rank_coordinates.py)で上記の保存結果だけを再集計した。Eの画素と目標値を使った調整はせず、床角の1座標を動かしたときのE予測の差を求めた。

2m地点・H2解0、Eを固定した±1px条件：

|床角と座標（画像基準）|1px端点での床位置変化の最大|Zの中央差分感度|
|---|---:|---:|
|奥・画像右のy|2.43cm|+2.35cm/px|
|奥・画像左のy|2.36cm|+2.30cm/px|
|奥・画像右のx|0.66cm|+0.37cm/px|
|奥・画像左のx|0.61cm|−0.26cm/px|
|手前・画像左のy|0.33cm|−0.30cm/px|
|手前・画像右のy|0.32cm|−0.29cm/px|
|手前・画像右のx|0.033cm|−0.031cm/px|
|手前・画像左のx|0.025cm|+0.020cm/px|

ここでの「画像右／左」は車体右／左の宣言ではない。`dZ/dpixel` は±1pxの中央差分であり、全域に使える線形換算式でも誤差保証でもない。反転未確定のまま、この順位を使って都合のよい角へ移すこともしない。

今回の次の改善対象は、まず**奥の2つのL字の外角とEの画像座標の根拠**である。遠側L字の画像のy位置をどこで読むかは、同じ閾値で繰り返し同じ値が出るだけでは正確と証明できない。従来の白い紙／コーン辺用レビュー機能へL字を「紙」と偽って投入することも避ける。

根拠：[座標別感度CSV](coordinate_ranking_r01/coordinate_sensitivity.csv)、[画像基準の順位CSV](coordinate_ranking_r01/group_ranking.csv)。全仮説・両解・両幅の768行を保持した。

## 5. 同一画像で生光線の点順を全て試す対照

「最初の姿勢を後半へ転用したため左右が合わなかった」可能性と、点対応そのものを分けるため、後半の各画像で固定4点の全24対応をfitした。生光線・正しい回転行列のみ、反射や高さ絶対値化なし。24対応×8画像×両解＝384行を保存した。

診断をあえて有利にし、**各画像でEに近い方の解を事後に選ぶことまで許した**下限を計算した。そのうえで同じ点対応を8画像へ使ったときの最大E誤差を求め、24対応の最小値を調べた。

|診断条件|全24対応の中での「最大E誤差」の最小値|
|---|---:|
|床上でEが計算可能な解を許す|約38.32cm|
|さらに各画像の再投影RMSが2px未満の解だけ許す|約40.11cm|

この「Eに近い解」の事後選択は、**診断上の下限を計算するためだけ**で、正当な精度検証・解の採用手順ではない。どの対応も採用していない。今回の4点座標・床寸法・E申告・K/Dという探索条件内では、同一画像の姿勢推定にしても点順だけで左右の食い違いを解決できなかった。実機に鏡像があるとの証明ではない。

根拠：[全384行](results_r01/all_raw_assignments.csv)、[条件付き下限](results_r01/raw_assignment_diagnostic.csv)。

## 6. 次の判断

1. 同一画像4点と背景相対回転の結果は別条件として残す。背景補正が安定しても、点の物理対応・左右・精度を自動承認しない。
2. 読取り精度の改善は奥の外角とEを優先する。画素幅、固定点測量、内部校正・撮影経路の不確かさが未確定の間は、「2mで数cm以内」と保証しない。必要精度自体もユーザー未指定。
3. 既に依頼済みの `intake_summary.json`・`received_frames.csv` は、受信処理のソースhash・profileと今回のsession/frameを照合するために使う。画像の点順探索や高さ59cmへのfitで来歴の不足を置き換えない。
4. 追加撮影は今回要求しない。実際の反転処理、liveモデルの採用・安全ゲート・走行・FFBも変更していない。
