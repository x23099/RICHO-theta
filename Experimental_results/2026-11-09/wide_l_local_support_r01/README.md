# L字の保留原因：色付き連結と輪郭の画素階段の分離

## 結論

**保留の一部は画像不足ではなく抽出処理の問題で、既存画像のまま改善できた。** 色差を連結の補助にし、短い輪郭全体から方向を求める1条件で、後半8枚全ての固定4点＋Eを読めた。

ただし、全条件が通るわけではない。**方法の自動採用、光線反転の確定、距離精度の承認、live・走行・FFBへの導入はしていない。** 今回も元画像の加工・書出しや追加撮影は不要だった。

前段：[L字の辺・小数画素読取りの監査](../wide_l_boundary_audit_r01/README.md)。同じ10枚・既存の凸頂点・KB4内部校正を使用し、前段ソース／結果は書き換えず別フォルダへ保存した。

## 1. 原因A：明るさだけではコーン側の色領域とつながる

奥・画像左のL字について、暗い画素だけを抽出すると、赤コーン側の色差の大きい暗い領域が同じ連結成分となり、探索ROIの端まで続く画像があった。

各画素の絶対色差を `max(B,G,R)−min(B,G,R)` とし、なし／60／80／100の4条件を比較した。HSVの「低彩度なら黒」という判定にはしていない。今回の黒テープにも撮影系の色かぶりがあり、比率の彩度では大きい値になるためである。uint8の差で桁あふれしないよう整数へ変換してから計算した。

閾値110、奥・画像左の例：

|frame|明るさだけの成分面積|同成分の絶対色差中央値|色差100以下で元角につながる成分面積|
|---|---:|---:|---:|
|038231|321px|206|23px|
|038464|326px|205|27px|
|054907|324px|204.5|26px|

元の凸頂点の色差は44～46で、これらの条件では点そのものを除去せず、外側へ続く色差の大きい成分だけを切り離せた。連結成分の抽出には[OpenCV `connectedComponents`](https://docs.opencv.org/4.5.5/d3/dc0/group__imgproc__shape.html)を使った。

**色差で人工的に切った線をそのまま物理境界としない。** 色差は連結の補助に限り、辺の位置は元の灰度から暗→明の一意な閾値交点を求める。灰度に境界がなければ保留する。元角が色差フィルタで消えた場合も、近傍の別の点へ移らず保留する。中性色の暗い連結は色差で切れないため、従来同様に保留する。

根拠：[成分の全記録](results_r01/components.csv)、[実装](analyze.py)。

## 2. 原因B：最初の斜め1画素が短い辺の判定を歪める

P1のEでは、短い辺の支持点不足と判定された一方、元の輪郭にはその先の点が存在していた。

f038231の一方の腕の例：

```text
角(320,391) → (321,390) → (322,390) → (323,391) → (324,390) …
```

従来は最初の `(1,−1)` を方向として固定したため、3点目がその方向へ進んでいないと扱い、支持点2点で打ち切っていた。これは実際に辺が2点分しか写っていないという意味ではない。

対照として、同じ弧長4／5pxの支持点全体の主軸をSVDで求めた。単独の直交画素ステップを即座に切らず、主軸方向での明確な逆走を検査する。**3点以上・支持範囲1.8px以上という下限は緩めていない。** 重複点・逆走・平行に近い2辺・弱い濃淡勾配等は引き続き拒否する。

サンプリング方向には[OpenCV `fitLine`](https://docs.opencv.org/4.5.5/d3/dc0/group__imgproc__shape.html)を利用し、最終的な辺と角は前段と同じKB4光線平面で計算する。Eの目標座標や高さ59cmは、この抽出関数に渡していない。

## 3. 色差と支持方向の全条件を保持

4色差条件×2方向推定×2弧長×4灰度閾値、合計3,072点・条件の観測を保存した。実物3,072点の測量ではない。固定4点とEが揃わない画像・条件433件も保存し、欠けた座標を整数点へfallbackして埋めない。

閾値110・弧長4pxで、後半8画像全てに同じ条件を適用した結果：

|色差上限|最初のstep方向を使う対照：全5点が得られた画像|支持点全体の主軸：全5点が得られた画像|
|---|---:|---:|
|なし|5/8|5/8|
|60|0/8|0/8|
|80|4/8|6/8|
|100|6/8|8/8|

色差を厳しくすれば常に良いわけではなく、60では必要な支持も削られた。弧長5pxも全般に良くなるとは限らず、色差100・主軸条件でも閾値110では3/8だった。全16条件を保持し、8/8の条件だけを成功結果として隠れて採用していない。

数値検査の下限・上限は前段と同じ。色差100・主軸・弧長4pxが今回の8枚で読めたことは、このsessionへの開発上の結果であり、未知の録画での一般化や精度保証ではない。

根拠：[全条件のcoverageと理由](results_r01/summary.json)、[支持点・濃淡境界の全観測](results_r01/observations.json)、[欠落による保留](results_r01/withheld_methods.json)。

## 4. 灰度の読取り経路は混ぜなかった

監査の途中で、同じPNGでもこの環境の以下の2経路には差があった。

- 従来：`cv2.imread(path, IMREAD_GRAYSCALE)`
- 比較：`cv2.imread(path, IMREAD_COLOR)` → `cv2.cvtColor(..., COLOR_BGR2GRAY)`

10枚では各画像の248,494～256,003画素で、前者が後者より1階調だけ小さかった。床付近の比較範囲でも4,109～5,443画素に差があった。座標系の反転やカメラ移動ではなく、**この環境での画像読込み／変換経路による数値差**である。他のOpenCV版や画像形式でも必ず同じ差になると一般化しない。

1階調でも閾値付近の連結性へ影響し得るため、今回の主計算は**従来の直接灰度読込みを固定**した。BGRは色差の補助にだけ使い、変換後灰度を主計算へ混ぜなかった。

色差なし・従来の支持方向の対照384件は、前段と**数値可否と座標が384/384一致**した。比較の途中で灰度経路が変わった改善ではないことを確認した。

根拠：[灰度経路CSV](results_r01/grayscale_route_audit.csv)、[従来結果の全照合CSV](results_r01/historical_controls.csv)。

## 5. 同一画像の固定4点だけで求めた条件付き幾何

以下は説明用に、8/8の座標が得られた **灰度閾値110・色差100・主軸・弧長4px・未確認H2・IPPE解0**を抜粋した。抽出後に同じ画像のA～Dだけをfitし、Eは検証に残した。全3仮説・IPPE両解を保存し、Eに近い解を自動採用していない。

|申告のE位置X,Z（m）|推定Zの2画像中央値|各画像の平面位置誤差|
|---|---:|---:|
|中央：0, 1.40|1.4099m|0.92～1.10cm|
|中央：0, 2.00|1.9921m|0.93～1.05cm|
|車体左：−0.20, 1.40|1.3934m|0.49～0.84cm|
|車体右：+0.20, 1.40|1.3994m|0.09～0.12cm|

この条件での床4点の再投影RMSは約0.074～0.178px、高さは約0.5741～0.5774m。高さ59cmへfitしていない。小さい再投影残差は固定点の測量・点ID・外角読取りや反転仮説の物理的正しさを保証しない。

**上表は実機の1cm精度の証明ではない。** 同じsessionで繰り返し開発しており、Eの申告値も既知である。未知の録画・人が独立確認した精密角・別の測量での未使用評価ではない。2画像は独立2実験でもなく、右の約0.1cmをmm精度と解釈しない。Zは車体原点からの前方成分で、カメラからの斜距離・コーン接触距離ではない。

また、8/8が得られたのは灰度閾値110の1条件であり、各配置2画像×4閾値の全8評価を通過したという意味ではない。別閾値で保留された条件もCSVへ全て保存した。

根拠：[全姿勢評価](results_r01/pose_evaluation.csv)、[条件・仮説・両解の集計](results_r01/group_metrics.csv)。

## 6. 検証

[最終検証記録](verification_r02/verification.json)：**新規19テスト成功、失敗・エラー・skip 0**。入力／ソース43hashを照合し、前段20件と既存79件は対象ソースが不変なことを確認して成功記録を再利用した。118件を今回実行したとは数えない。

新規試験で、色付きの連結だけ切れること、中性色の暗い連結は保留されること、元の角が消えた場合に別の点へ移らないこと、色で切っただけの境界を灰度交点と偽らないこと、画素階段での3点支持、重複点を数に足さないこと、欠落時にfit／fallbackしないこと、Eを変えても床4点のfit入力が変わらないこと、元画像不変等を確認した。

初回の[verification_r01](verification_r01/verification.json)は1件失敗した。合成画像の暗20・明180に対して閾値110を「半分の明るさ100」と取り違えたテスト期待値が原因だった。線形な閾値交点は0.5pxではなく `(110−20)/(180−20)=0.5625px` である。期待値を正して、許容差も0.05pxから0.01pxへ厳しくしたうえで19件全て成功した。解析コード・実画像の結果・閾値は変更しておらず、初回失敗の記録も残した。

## 7. 次の対象と変更範囲

1. 元画像のままで読める範囲は広がった。保留を理由に新しい撮影を要求しない。
2. 現在の外角と固定点ID、撮影経路・左右仮説の物理的対応の確認は依然必要。全ての左右は前進方向基準と回答済みで再質問しない。
3. 未提出の受信来歴 `intake_summary.json`・`received_frames.csv` は、ソースhash・profileとsession/frameの照合に使う。色差や画素感度の改善で来歴不足を置き換えない。
4. 数値が近い条件をruntimeへ自動採用せず、既存の条件付き比較と、確認済み物理校正を分ける。走行・FFB・liveの安全判定には接続していない。

Git操作、日報・引き継ぎの追加整理も今回行っていない。
