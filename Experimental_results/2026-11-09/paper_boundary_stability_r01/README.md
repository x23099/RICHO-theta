# 既存床画像での紙外周・角位置補正の安定性（2026-11-09）

## 結論

**角位置補正によって、同一画像内の初期位置・閾値への依存を減らせる例があった。ただし距離の正しさは別であり、ライブ採用は見送る。**

半窓4px（探索範囲9×9px）では、以前の閾値処理が出した異なる四角形からほぼ同じ結果へ収束した。一方、この結果のdf33遠方フレームは約**1.871m**で、ユーザー申告の2.00mとの差は約−12.9cm残る。手動紙角の同フレーム1.983mからも変わる。**座標が安定したことを、物理的な紙角・床姿勢・測距の正しさとして扱わない。**

今回、旧抽出からの角補正、境界の明暗証拠、初期位置のストレス試験、全床仮説の比較をオフラインで実装・実行した。元画像と人の確認JSONは不変。live設定・支持点ゲート・ROS/FFBには変更なし。Git commit/pushは依頼されておらず実施していない。

## 方法と制限

- 対象：既存の紙2枚、b559 / f5755、df33 / f2292。録画や別sessionの校正を追加・転用しない。
- 元の明示ROI、gray閾値150/170/190 × 輪郭近似係数0.02/0.025/0.03/0.04を再利用。24条件のうち13条件で4頂点が得られ、残り11は保留。4頂点を強制補完しない。
- 13四角形について、補正なし＋OpenCV `cornerSubPix` の半窓2/3/4pxをすべて保存し、**52候補**を評価。半窓は探索窓の半幅で、実窓は5×5、7×7、9×9px。[OpenCV公式API](https://docs.opencv.org/4.13.0/dd/d1a/group__imgproc__feature.html) の定義を確認した。実行環境のOpenCVは4.5.5である。
- 初期値は**旧輪郭から得た4隅だけ**。手動座標から開始せず、距離の正解へ合わせて窓や閾値を選ばない。反復上限50、停止移動量0.001pxは数値計算条件であり、その精度保証ではない。
- 各候補について紙寸法2対応・平面解2通り・高さ2方式を維持し、計416モデル応答。比較表は以前からの先頭系列 `as_listed_s0_image_plane_plus_thickness` を固定表示するだけで、採用・順位付けではない。
- 手動座標との画素差は**人の目視との比較**。独立測量の正解誤差ではない。同じ2枚での診断であり、未知画像・別場所・フレーム間変動の独立検証は未実施。

## 1. 人の確認座標との比較

旧主条件から開始した場合の、4角の平均画素差を示す。

|対象|補正なし|半窓2|半窓3|半窓4|
|---|---:|---:|---:|---:|
|b559|1.404px|1.313px|1.262px|0.651px|
|df33|0.815px|0.327px|0.490px|0.757px|

根拠：[candidate_comparisons.csv](results_r02/candidate_comparisons.csv)、[角ごとの比較図](results_r02/corner_refinement_comparison.png)。b559の左上は半窓4で3.684→0.527pxとなったが、df33の左下は0.411→1.382pxと離れた。**全角・全画像で一様に改善したわけではない。**

b559左上は半窓2/3では旧初期座標と同じ値が返った。OpenCV 4.5.5には推定点が初期位置から窓幅を超えて動いた場合に初期値を返す分岐があるので、「返却値が動かない＝正しい角へ収束」とは言えない。[実行版の公式実装](https://raw.githubusercontent.com/opencv/opencv/4.5.5/modules/imgproc/src/cornersubpix.cpp) を確認した。今回、その分岐を実行時に直接計装したわけではないため、各不動点の原因をその分岐と断定はしない。

## 2. 初期位置をずらした場合

旧主条件の4角に対し、無変更1＋8座標の各±0.5px=17個の初期四角形を試した。各cornerで17個の異なる値を試したという意味ではなく、他角だけを動かした重複入力も含む。同じ画像の数値初期値試験で、実カメラの時間変動試験ではない。

|対象|半窓2：最大出力変位|半窓3：最大出力変位|半窓4：最大出力変位|
|---|---:|---:|---:|
|b559|2.114px|3.379px|0.00141px|
|df33|0.00120px|0.000454px|0.000407px|

無変更初期値の補正出力を基準とした全4角の最大。根拠：[initial_seed_stability.csv](results_r02/initial_seed_stability.csv)、[全408角記録](results_r02/initial_seed_trials.csv)。同じ値への収束が見えるが、これは小数点以下の物理精度の証明ではない。

## 3. 閾値依存と距離

全ての成功した旧輪郭設定から開始し、固定支持点を同じまま再計算した範囲。

|対象・掲載フレーム|補正なしの条件付き距離|半窓4の条件付き距離|
|---|---:|---:|
|b559 / f35562|0.95690～0.96388m|0.974614～0.974617m|
|df33 / f64232|2.05923～2.39158m|1.871117～1.871124m|

根拠：[conditional_geometry.csv](results_r02/conditional_geometry.csv)、[閾値・窓と距離の図](results_r02/parameter_stability_ranges.png)。同一画像・複数処理条件の比較で、各条件は独立な録画ではない。小数桁は計算結果の再現用で、実距離精度を表さない。

半窓4の紙由来高さ（板厚15mmを加算）はb559約580.75～580.77mm、df33約563.83mm。持越しの床上高さ590mmと、とくにdf33で約26mmの差が残る。全ての条件で外部590mm固定の別仮説も残しているが、申告高さへ合わせて法線や寸法をフィットしていない。

支持点・実測申告の対応は [前段の分離検証](../reviewed_coordinate_audit_r01/README.md) を参照。出力は条件付きカメラ直下水平距離、申告基準は車体中心から台座手前辺中央で、その原点対応が独立に測量検証されたわけではない。f32654の参考点は**拒否済み文脈候補でlive出力ではない**ことを `summary.json` の `source_probes` に保持する。

## 4. 境界の画素証拠

紙の各辺について、端の光線をKB4へ再投影した軌跡に沿い、辺の内外±0.5/1/2pxの灰度差と±3pxの勾配位置を記録した。魚眼上の直線辺を単純な画素線分とせず、中央カメラモデルの直線辺軌跡として評価している。

|b559上辺の候補|内外±1pxの灰度差中央値|内側が明るい標本の割合|
|---|---:|---:|
|旧主輪郭|1 / 255|51.5%|
|半窓4補正|39 / 255|97.0%|

この例では白い内側を支える画素証拠が増えた。一方、補正後でも上辺の最大正勾配の中央値は想定辺から内側約+0.625px、下辺では約−0.875pxに位置する。この量は端点からのモデル軌跡・灰度補間・印刷や反射にも依存し、そのまま物理的角の訂正量とはしない。

根拠：[boundary_evidence.csv](results_r02/boundary_evidence.csv)。各辺33点は相関した標本で、33個の独立観測とは扱わない。「灰度差20以上の割合」も感度を観察する生の診断値で、採用ゲートとして校正した閾値ではない。勾配行列の固有値も [corner_observations.csv](results_r02/corner_observations.csv) に保存するが、その値だけで紙外周の物理的同一性を証明しない。

## 判断と次の作業

- 角位置の安定化は可能な例がある。ただし、同じ画像で安定して似た結果が出ることと、床幾何が正しいことは区別する。
- **今回のサブピクセル補正をそのままliveへ組み込まない。** 最も手動に近い窓をsessionごとに選ぶ対応や、最も実測に近い床仮説の採用は行わない。
- 既存2枚の角抽出だけを変更しても、全物理不整合を解決したとは言えないことが分かった。続編の [同一session別画像の棚卸しと比較](../same_session_reference_audit_r01/README.md) では、もう1枚の紙画像を確認したがほぼ同配置であり、独立した物理基準とは判定していない。学校PCに追加データが残っているとの回答を受け、保存先を確認中。小さな紙の同じ4隅だけを何度も調整して、検証データへ合わせ込む方針にはしない。
- 追加撮影を相談するのは、既存画像から得られない独立した床姿勢・紙端の情報に不足を限定できた場合。現時点で追加撮影・端末操作の依頼はない。
