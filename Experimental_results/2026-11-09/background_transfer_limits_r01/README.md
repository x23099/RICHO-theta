# 背景回転補正の通過・保留範囲の監査

続き：[同一画像の床4点の画素感度・点対応監査](../same_frame_floor_sensitivity_r01/README.md)。背景補正と分けて、角の読取りずれと生光線の全24点対応を調べた。

## 結論

**背景の追跡・回転推定は今回の保存画像では比較的安定していたが、それだけでは「カメラ中心が動いていない」「床までの距離が正しい」と判定できない。** 背景残差のゲートを距離の合否判定へ昇格させない。

前段の[初回床校正＋背景相対回転](../background_rotation_transfer_r01/README.md)を変更せず、以下を追加した。

- 合成の並進120ケース、正しい静止／回転3ケース、追跡異常等8ケース。
- 実画像8枚の保存追跡点から、推定用の空間セルを1つずつ除いた109ケース。
- 新規16テスト成功。変更のない既存79テストはソースhashを照合して成功記録を再利用。

元PNGの加工・再出力、校正候補の採用、live処理・安全ゲート・ROS/FFBの変更はない。実機の並進を測った試験でも、新規録画の精度試験でもない。

## 1. 合成試験の条件

[analyze.py](analyze.py) は既存の `estimate_background_rotation` をそのまま呼ぶ。背景残差中央値0.6px以下、90%点1.5px以下、回転5度以下など、前段の条件は固定し、Eの距離誤差を見て調整していない。

|項目|条件|
|---|---|
|内部校正|前段と同じKB4候補。K/Dは固定|
|背景の対応点|上部領域の重複なし35点。推定18、検査17|
|背景の光学Z|3／5／10／20m、3mと10mの交互配置|
|カメラ中心の並進|光学x／y／zの各方向へ1／3／5／10cm|
|真の回転|光学y軸0度または0.8度。上記との組合せ120ケース|
|合成の初期位置|床上高さ0.59m、前方0.02m・左−0.03m。実機へ採用する値ではない|
|評価対象|前方1.0／1.4／2.0mと、1.4m地点の左右0.2m、計5点|

光学Zは光軸方向成分であり、各特徴点までの斜距離ではない。背景はノイズなし、追跡は特記以外正しい。距離の真値は回転推定・検査に渡さず、通過後の誤差評価だけに使う。

初期の床座標系を固定し、真のカメラ中心だけを移す。真の現在位置は `t_current = t_reference + R_floor_from_reference × shift_optical`。これに対して評価対象の方式は中心を初期位置に固定したまま回転だけを更新する。正しい並進と回転を両方使えば床点を復元できることも、別のテストで確認した。

**これは固定された校正時の床座標系での点位置の評価である。走行中の現在base_link座標、カメラ直下からの水平距離、コーンへの接触距離とは区別する。** 下表の「平面位置誤差」は前後・左右を合わせた誤差であり、そのまま距離スカラーの誤差とは呼ばない。

## 2. 検査を通過しても並進の影響が残る

120ケースのうち102ケースが背景検査を通過した。これは組合せ表の件数であり、実機での通過確率・故障率ではない。通過ケースの最大平面位置誤差は約38.7cmだった。

真の回転0度、背景光学Z=5mでの抜粋：

|真の並進|背景検査|検査残差中央値|5点中の最大平面位置誤差|
|---|---|---:|---:|
|横1cm|通過|0.039px|0.95cm|
|横5cm|通過|0.194px|4.77cm|
|下1cm|通過|0.089px|2.92cm|
|下5cm|通過|0.445px|15.57cm|
|前1cm|通過|0.053px|1.57cm|
|前5cm|通過|0.265px|7.73cm|

光学y正方向はこの合成姿勢では床方向。カメラ高さが変わるのに、方式は古い高さを保持するため影響が大きい。背景光学Z=20m・下方向10cmでは、残差中央値約0.223pxで通過しながら最大約38.74cmになった。**実機が10cm動いた、今回の提出画像に38.7cmの誤差がある、という意味ではない。** 未観測の運動を残差だけから除外できない反例である。

静止・正しい0.8度回転の陽性対照3件は全て通過し、最大誤差は浮動小数点丸め相当（約2.3×10⁻¹⁵m）。正しい前提の下では式が閉じることと、実機で前提が正しいことを分けた。

根拠：[全120ケースCSV](results_r01/synthetic_motion_metrics.csv)、[入力・推定・各点誤差の全JSON](results_r01/synthetic_motion_cases.json)、[陽性対照](results_r01/positive_controls.json)。

## 3. 追跡異常で弾けるもの／弾けないもの

|合成した条件|結果|診断上の意味|
|---|---|---|
|検査点だけ横8pxの誤対応|拒否|推定用と独立した点で矛盾を検出|
|推定点だけ横8pxの誤対応|拒否|誤った回転を検査点が検出|
|5点ごとに横8pxの誤対応|拒否|この配置の部分的な追跡崩れは検出|
|対応が10点に減少|拒否、回転なし|点不足時に単位回転や過去値を発明しない|
|30点あるが横幅40pxに集中|拒否、回転なし|点数だけで通さない|
|正しい6度の回転|拒否|残差が小さくても小回転条件の範囲外|
|背景の誤対応全体が0.8度回転として整合|通過|整合した誤対応は残差だけでは区別できない|

最後の対照は「カメラも床点も本当は静止だが、背景対応だけが偽の回転を示す」と明示的に作った入力である。検査残差はほぼ0でも、床点の最大位置誤差は約9.65cmになった。実画像でこの誤対応が発生した証拠ではなく、検査の識別範囲を示すもの。

拒否ケースでは、このオフライン評価の距離・点誤差を `null` とし、`distance_withheld=true`。通過ケースでも `physical_metric_verified=false`、`usable_for_ffb=false` を維持する。実際のlive表示へこの処理を追加したわけではない。

根拠：[追跡対照CSV](results_r01/tracking_metrics.csv)、[対応する全条件と結果](results_r01/tracking_controls.json)。

## 5. 現時点での進め方

1. **背景補正は条件付き比較として残す。** 前段でEの一致が改善した結果自体は取り消さないが、背景検査通過だけで固定床モデルを自動採用しない。
2. **同一画像の固定4点から求める床姿勢を、比較の基準側に残す。** カメラ中心の並進を固定する方式との違いを見られる。これも物理的な点対応・光線左右が未確定の間は精度承認ではない。
3. **画素閾値を距離の正解へ合わせて厳しくするだけでは解決しない。** 整合した偽回転は残差0でも通り、遠い背景で並進を見逃す条件もある。今回はゲート変更・live導入をしていない。
4. 次は既に依頼済みの受信来歴 `intake_summary.json`・`received_frames.csv` と固定点の物理対応を照合する段階。左右は前進方向基準と回答済みで再質問しない。新たな撮影は今回要求しない。

入力ログが揃うまでにできる幾何の対照試験は増えたが、それで未確認の反転仮説や物理測量を置き換えない。走行時のcamera/base_linkの運動・TFへ接続する検証とも分離する。
