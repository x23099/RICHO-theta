# 床4点＋検証Eの初回幾何診断（2026-11-09）

追検証：[外角同定・24点順・背景移動・同じ画像の4点を使った比較](continuation_report.md)。以下は最初のP0姿勢を固定した計算であり、最新の同一画像内での再推定とは条件が異なる。左右・反転の未確認事項は追検証でも残る。

## 結論

予定した5条件・計10枚で、画像だけの暫定点抽出、固定4点だけの床姿勢fit、独立Eの評価まで実行した。**現在は `WITHHELD_HANDEDNESS_AND_POINT_REVIEW_REQUIRED`。校正成功・距離完成・live採用とはしない。**

Eの申告は、f051180/f051342＝前進方向を向いたときの車体左20cm、f054907/f055094＝車体右20cmとして確定した。画像上ではこの左右が逆に見える。固定A～Dにも同じ対応を仮定すると、現在のKB4の光学軸定義ではカメラが床下にある解となる。左右申告を勝手に訂正したり、床下解の高さを絶対値化したりして通さない。

追加回答「全ての左右は全身方向に対しての左右です」は、直前の確認と同じく**全点とも前進方向を向いたときの車体左右**という意味として記録した。固定点とEで左右の言葉の定義を変えない。観察者がカメラと向かい合った左右として再解釈せず、この定義についての再質問はしない。なお、左右という言葉の定義が確定したことと、ラベルのない各画像点の物理IDが独立に確定したことは区別する。

これは**鏡像が実在するという確定診断ではない**。固定A/B/C/Dの個々の画像対応、送信元での撮影向き・キャプチャ側の設定、左右の座標解釈のいずれかが未整合である可能性を残す。固定点のIDは画像に書かれておらず、Eの左右だけで4点の物理IDを断定できない。

## 入力と方法

- session：`159c37ad534a4ac0b96ca69791713567`、1280×720の無加工WebRTC受信PNG。10枚のパスとSHA-256は [input_provenance.json](results_r01/input_provenance.json)。元PNGはDownloadsにあり、再保存・注釈・拡大・切抜きファイル出力はしていない。
- 既存の10/21 angular KB4内部校正をハッシュ検査して固定。内部校正の再学習・590mmへの高さ合わせは行わない。過去録画の床姿勢を流用せず、今回P0の4点から新たに推定する。
- 外角の粗い位置を解析者が目視で指定し、その近傍の暗い輪郭の頂点を閾値110で暫定抽出。閾値90/100/120も記録する。**物理的に正しい外角の人手レビューは未実施**。近傍頂点は内角・輪郭ノイズへ寄る可能性があるため、暫定座標である。
- 固定点の予定座標は操作者のX右・Z前から、床のx前・y左・z上へ `(x,y,z)=(Z,-X,0)` と変換する。予定値の測量不確かさは未申告。
- P0のf020063とf020493を個別に使い、各4点のみで `planar_floor_pose_candidates` を実行。**Eの8枚はfitにも解の選択にも用いない**。
- [OpenCV公式PnP資料](https://docs.opencv.org/4.13.0/d5/d1f/calib3d_solvePnP.html) に従う平面点のIPPEの2解を保持する。生魚眼の画素を直接ピンホール式に入れず、既存KB4光線から正規化透視点へ変換する。実行OpenCVは4.5.5。

## 点の読取り・安定性の留保

- 閾値を90～120に変えると、同一画像内の暫定頂点が最大3px動く。整数輪郭点であり、サブピクセル精度は主張しない。
- 同一sessionの固定点の暫定位置は、初回から最大2.83px異なる。点の選択揺れ・撮影の微小変化をまだ分離しておらず、この値だけで「カメラが動いた」とは判定しない。
- f020063の校正点の座標を1成分ずつ±1px動かすストレス試験では、H2解0の高さ0.5538～0.5695m、中央2mの前方推定2.0190～2.0725mだった。これはノイズ分布・信頼区間・同時8成分変動の最大誤差ではない。
- 同じストレス結果のH1を再確認すると、±0.5/1px・8成分の単独変更で、解0は高さ−0.5695～−0.5538m、解1は−0.3888～−0.3761m。各32ケース、計64解の全てが床下だった。今回試した1成分の微小な読取り変化だけでは高さの符号は解消しない。ただし、画像点の取り違えや測量誤差全般を排除する試験ではない。
- 小さかった紙1枚より点の広がりは確保できたが、点の物理IDと読取りの正しさは別問題として残る。
