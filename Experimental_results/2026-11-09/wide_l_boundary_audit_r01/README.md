# L字外角の辺・小数画素読取りの監査

続き：[色付き連結と輪郭の画素階段の分離](../wide_l_local_support_r01/README.md)。保留の局所原因を分け、元画像・従来灰度経路を維持したまま、1条件で後半8画像の固定4点＋Eを読めた。以下の元結果・コードは変更していない。

## 結論

**輪郭の整数頂点に代えて、テープの辺を使う読取り候補を作れた。ただし、全画像・全条件で読み取れる方法にはなっておらず、liveへは採用していない。** 2m地点で約1.992mとなる例があるが、それに近い条件を選んで精度合格とはしない。

また、小数画素の角補正で入力座標がそのまま返る例を確認した。**値が小数であること・処理が例外なく終了したことは、角が精密に補正された証拠ではない。** 角補正をそのまま採用する案は保留した。

前段：[同一画像の床4点の感度](../same_frame_floor_sensitivity_r01/README.md)。今回は既存10 PNGを読み取り、画像の変更・注釈・切り抜き等の書出し、内部校正変更、live反転、ROS/FFB・安全判定の変更は行っていない。追加撮影も要求しない。

## 1. 比較した方法

全てsession `159c37ad534a4ac0b96ca69791713567` の元1280×720 PNG、既存のL字外角seedと閾値90／100／110／120を用いる。目標距離や高さ59cmを抽出関数へ渡さず、画像座標の抽出後だけ幾何を比較する。

|方法|内容|注意|
|---|---|---|
|元の整数凸頂点|既存の輪郭近似の凸頂点を再現|凸頂点でも正しい物理外角の確認ではない|
|輪郭支持点の辺交点|外角から輪郭の両側の短い支持点を取る|整数の輪郭画素中心に依存する対照|
|濃淡境界の辺交点|輪郭に沿って外向きの暗→明の閾値交点を補間し、両辺を求める|局所濃淡・細いテープ・境界の丸まり等の影響は残る|
|角の局所補正|OpenCV `cornerSubPix`、半窓2／3px|内外の辺や端点へ引き寄せられる可能性。別途初期値依存を調べる|

辺のサンプリング方向だけは[OpenCV `fitLine`](https://docs.opencv.org/4.5.5/d3/dc0/group__imgproc__shape.html)で求める。魚眼画像の長い直線弦をそのまま床の直線と仮定せず、境界の各点を既存KB4で単位光線へ戻し、**直線の像が作る光線平面**をSVDで当てる。両辺の平面の交線を画像へ再投影して角候補とする。

[OpenCV `cornerSubPix`](https://docs.opencv.org/4.5.5/dd/d1a/group__imgproc__feature.html)は画像勾配を使う局所の角補正であり、L字の物理的な外角や測量点を認識する機能ではない。今回は独立した比較対象として扱い、結果が2mへ近い窓を採用しない。

今回の診断条件：各辺3点以上、支持範囲1.8px以上、辺の再投影RMS0.65px以下、交差角のsin0.2以上、元凸頂点からの移動3px以下。濃淡境界は外向きの閾値交点が1つで、勾配20階調/px以上のものだけ。支持点が少ない・輪郭が探索窓へ達する・勾配が弱い場合は保留し、元の整数点へ暗黙に戻さない。

これらは物理精度を保証する閾値ではない。辺の平面当てはめも、テープが真っ直ぐで、正しい外側の辺を観測できている場合のモデルである。

## 2. 探索窓の切断と、元画像内での拡大

[初回スクリプト](analyze.py)では既存seed周囲33×21pxの局所探索を再利用し、1,728点・条件の観測を保存した。元の整数凸頂点192件を全て再現したが、辺交点の方法では探索窓でテープの端が切れる条件があった。これを撮影不足と判断せず、[探索窓の拡大](audit_expanded_roi.py)を追加した。

元の凸頂点の候補IDを変えず、その点を含む連結成分だけを49×33px／65×41pxの範囲で調べた。拡大した範囲の画像をファイルへ書き出してはいない。ROIの端へ連結成分が達する場合は保留を維持し、他の暗い物体やL字へ乗り換えない。

探索窓・辺の支持長を全て保持した結果：

|方法（両探索窓で同じ結果）|座標が得られた点・閾値条件|閾値110で固定4点＋Eが全て得られた後半画像|
|---|---:|---:|
|輪郭支持、弧長4px|143/192|5/8|
|輪郭支持、弧長5px|158/192|5/8|
|濃淡境界、弧長4px|133/192|5/8|
|濃淡境界、弧長5px|142/192|3/8|

192は48マーカー観測×4閾値で、独立した192個の物理点ではない。拡大後1,536点・条件を保存し、固定4点＋Eが揃わない200画像・条件を保留した。探索窓の2サイズで共通に得られた座標は一致したが、**探索窓に対する一致は物理的正しさの証明ではない。** 保留原因には短い支持、弱い勾配、探索窓外へ続く暗い連結成分が残っており、これら全てが元画像の情報不足とはまだ断定できない。

閾値110・濃淡境界・弧長4pxでの主な保留は、P1のEの支持点不足と、一部画像の奥・画像左の連結成分が探索範囲を越えることだった。後半の全8画像をこの方式で統一して測れたわけではない。

根拠：[拡大後summary](expanded_roi_r01/summary.json)、[全境界観測](expanded_roi_r01/boundary_observations.json)、[保留と欠落した点](expanded_roi_r01/withheld_methods.json)。

## 3. 同一画像4点からの距離比較

座標が揃った場合だけ、固定A～Dからその画像の床姿勢をfitし、Eを後から評価する。既存3仮説・IPPE両解を保持する。ここでもEは姿勢fitに使わない。

2m地点の2画像、**未確認H2・IPPE解0**の比較抜粋：

|読取り|閾値110のZ代表値|4閾値×2画像で得られたZ範囲|数値あり条件数|
|---|---:|---:|---:|
|整数凸頂点|1.9833m|1.9833～2.0239m|8/8|
|角補正、半窓2px|1.9955m|1.9891～2.0188m|8/8（数値の存在のみ）|
|角補正、半窓3px|2.0803m|2.0735～2.1296m|8/8（数値の存在のみ）|
|輪郭支持の辺交点、弧長4px|1.9490m|1.9490m|2/8|
|濃淡境界の辺交点、弧長4px|1.9924m|1.9920～1.9927m|2/8|
|濃淡境界の辺交点、弧長5px|1.9940m|1.9940m|1/8|

「代表値」はその条件で数値が得られた画像の中央値で、全画像へ使える精度ではない。特に辺交点の範囲が狭いのは、保留された閾値・画像を含められないことも関係する。**成功した少数だけの範囲を信頼区間や精度上限にしない。** 角補正で1.9955mが出たことも、次節の不成立監査を無視して採用理由にはしない。

Zは校正時の車体原点からの前方成分。コーン接触距離の新たな測定ではない。鏡像・固定点ID・画像の外角の物理対応も未確定のまま。

根拠：[全方法・全配置・両解の集計CSV](expanded_roi_r01/comparison_metrics.csv)、[座標が揃った場合の全姿勢評価](expanded_roi_r01/pose_evaluation.csv)、[従来点／角補正の評価](results_r01/pose_evaluation.csv)。

## 4. 小数画素の角補正が不成立でも、入力値を返す

各元凸頂点から開始位置を0／±0.5px（xまたはy）へ変え、半窓2／3pxを調べた。48観測×2窓×5初期値＝480計算、96組の初期値集合を比較した。

|確認|件数|
|---|---:|
|一部でも入力位置がそのまま返った集合|50/96|
|全5初期値で、その入力位置がそのまま返った集合|40/96|
|入力位置のそのまま返却がなく、出力間隔0.1px以内だった集合|46/96|
|初期値による出力点間距離の最大|約2.592px|

全5初期値がそのまま返る場合、出力が「安定した角」に収束したのではなく、初期位置の1pxの広がりをそのまま保持している。APIが例外なく終了しても、これを精密な角の定位成功とは数えない。`available=true` だけだった初回比較と、ここでの信頼性確認を区別した。

46組も**初期値に対する整合性を通過しただけ**で、真の外角や画素精度を検証した数ではない。細いL字で内外の勾配が同じ窓へ入ること、テープの厚さ・丸まった境界や圧縮の影響は残る。実行時の判定へ新しい閾値を追加したわけではない。

根拠：[初期値試験](expanded_roi_r01/seed_stress.json)、[初期値集合ごとの分類CSV](reliability_r01/refinement_reliability.csv)、[判定コード](audit_reliability.py)。

## 5. 真の外角が分かる合成画像での対照

カメラ画像ではない合成L字を8種類（太さ1／2／3／4px、回転0／20度）作り、既知の外角 `(320.25,390.6)` と比較した。1画素内16×16の面積サンプリング、暗20・明200の条件で、画像はファイルへ書き出していない。

8種類のうち2種類は最初の凸頂点を得られず、全方法を保留した。残る6種類×7方法と合わせ、44行を保存した。これは実機のノイズモデルではない。

例：太さ2px・回転0度・閾値110での既知外角との差：

|方法|合成の外角位置誤差|
|---|---:|
|濃淡境界の辺交点、弧長4px|約0.091px|
|角補正、半窓2px|約0.300px|
|角補正、半窓3px|約0.761px|

角補正の窓サイズを変えるだけでも外角からの偏りが変わった。濃淡境界の方法も0誤差ではなく、今回の単純な合成条件で差を調べられたに過ぎない。実機へ同じ0.091pxの精度を主張しない。

根拠：[全合成対照JSON](reliability_r01/synthetic_controls.json)。

## 6. 判断と次の対象

1. **元の床4点・Eの整数座標を無断で置き換えない。** 数値が2mに近い方法を採用せず、辺交点は比較候補として保存する。
2. **角補正は有限値の有無だけで評価しない。** 同じ入力が返る・別の収束先へ動く・内外のどちらの辺を見ているか未確認の点を、精密座標とみなさない。
3. 残った保留は、P1のEの短い支持と、奥・画像左の暗い連結成分を優先して個別確認する。ここでの方式が失敗したことだけで、保存画像から得られる情報が尽きたとは結論しない。
4. 受信来歴の `intake_summary.json`・`received_frames.csv`、固定点ID・左右・外角の物理対応も依然未確定。全ての左右は前進方向基準と回答済みで再質問しない。今回の辺読取りで、それらの不足を置き換えない。

今回の結果はオフライン比較まで。追加撮影、校正の採用、live反転・ROS・走行・FFBには進めていない。
