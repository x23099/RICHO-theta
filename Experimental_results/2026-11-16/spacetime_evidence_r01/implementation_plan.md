# 時計・車体座標の根拠整理と保存ログ診断

2026-11-16。対象は保存済みr03の時計情報と既存の条件付き光学床面ベクトル。実行系・操縦・ROS・FFBを変更しない。

1. 元ROS整数stamp、sender callback/snapshot、receiver受信の経過差を集計する。別時計の差は通信遅延と名付けず、時計差・ドリフト・callback/伝送遅延が混ざる観測として扱う。
2. 片道記録について、一定相対歩度の仮定下でも2つの異なるoffsetと非負遅延が同じ記録を説明できる例を示す。実offsetや誤差上限を生成しない。
3. 4timestamp往復の非負遅延条件によるoffset区間を合成検証。往復対称を仮定した一点推定とは区別する。実交換・時計調整は行わない。
4. カメラ原点と直下点の違いを明示した剛体変換式を合成検証。前進x/左y/上z、光学右x/下y/前zを区別し、reflectionや非剛体行列は拒否する。実データへ未測量の変換を適用しない。
5. 現取付の変換として採用できない既存候補をSHA付きで記録し、必要な時計/寸法情報と次の読み取り確認をまとめる。過去の床測距・左右定義・実測を無効にしたり再撮影を要求したりしない。

根拠: 既存driver_motion_spatial.py/motion_time_join.py、ROS2 Clock and Time、REP103、RFC5905。外部の時計/軸規約を本機の検証済み設定と同一視しない。
