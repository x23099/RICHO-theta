# 上端接触だけを評価するオフライン比較候補

## 実装結果

`src/cone_upper_support_candidate.py::observe_upper_completion` を追加した。
従来の主距離経路・色分離候補・横方向補完は変更していない。
新モジュールは**オフライン専用**で、live engine / worker / GUI / ROS / FFBから呼ばれない。
既存の受信コマンドへ新フラグを足す実装ではなく、現GPUプロセスにも影響しない。

元の比較候補で点が取得済みなら、そのpoint/support/reason/selected_colourをそのまま維持する。
上端接触によって取得できない場合だけ、独立した候補として次を評価する。

1. 元のseedで選択された赤または黄を維持する。失敗後の別色への切替はしない。
2. 接触辺は**上端だけ**。左右・下端・複合接触の救済はしない。
3. 左右・下端は従来の4pxのまま。上方向だけp・2pへ拡張する。
   pは `clip(ceil(0.2×bbox高さ),8,16)`、最大32px。際限なく探索しない。
4. 2段階の領域で成分が閉じ、seedの同一成分が最大成分に対応し、
   全体の競合輪郭・観測点の既存検査も成立する必要がある。
5. 2段階で同一の色成分画素・同一のsupport/pointが得られ、元の成分画素を全て保持する。
6. 元の領域で観測できていた下端列と、新しいsupportが完全一致する。
   推定直線・外挿点・新しい底面を作らない。
7. 選ばれた点は元の実support列に含まれ、元の浮動小数bboxの内側にある。
   この枠内条件を丸めや余裕幅で緩めない。

高さ・HSV範囲・既存の3フレーム連続品質確認・500ms条件・距離モデルは変更しない。
新関数はあくまで単一画像の未検証候補で、時間品質の受理を与えるAPIでもない。
利用する場合は既存の時間品質ゲートが別途必要。新テストでも初回2行が保留されることを確認した。
全結果にcontrolling_distance / physical_metric_verified / floor_contact_verified / usable_for_ffb=falseを保持する。

## 既存画像での検証範囲

入力は [3配置のmanifest](../floor_df33e833_multidistance_r01/cases.json) のうち、
同frame PNGがある1mのf061948、2mのf064232。
元の1280×720 PNGとhashを前後で保持し、注釈・切抜き・縮小画像は保存していない。

| 条件 | 従来 | 新比較候補 | 意味 |
| --- | ---: | ---: | --- |
| 実際に保存された同frameの2画像 | 2/2で点あり | 同じ2/2の点を維持 | 実画像の新しい救済は0件 |
| 画像固定・bbox上下端±1pxの18条件 | 15/18で点あり | 16/18で点あり | 検出枠を変えた反実仮想試験 |
| 上記のうち1mの9条件 | 6/9 | 7/9 | 上端接触1条件だけ追加取得 |
| 上記のうち2mの9条件 | 9/9 | 9/9 | 既存候補を維持 |

追加取得は、1m保存画像でbbox上端+1px・下端+1pxとした条件。
上端+1px・下端-1/0pxの2条件は、点y=419が元のbbox下端を超えるため引き続き拒否する。
上端を閉じられたからといって、元の枠内条件を無視してはいない。

**18条件は18枚の新しい実映像ではない。** 保存PNGに記録された元の検出枠と、
そこから計算上変更した枠を区別して `bbox_counterfactual.csv` へ記録する。
1mの実ログで保留した81件のnative画像は今回存在しないので、
86.5%から何%へ改善するかはまだ測定できない。65件の支持点欠落や16件の再確認待ちを
この比較候補で実際に解消した、とは報告しない。
距離の過大推定や床板の角の精度が、この実装によって改善するわけでもない。
