## 距離が出なかった理由

### 1. コーン輪郭の切り出し不足

`colour_contour_reaches_roi_edge`が3,985件。現行実装はYOLOのbboxを四方4 px広げた画像領域で赤・黄を抽出し、主輪郭がその領域端へ接していれば、切れた形から下端を作らないよう保留する。

ここでいうROI端は、起動時の`--target-roi 270 0 350 720`とは別。起動引数のROIはbbox中心で対象を選ぶだけであり、これを広げるだけでは下端切り出し問題は解決しない。

ただし現行ログにはbbox座標や検出ごとのconfidenceを保存していないため、フレーム4903のどの端に接したか、bboxが狭いのか、背景の同色物がつながったのかは、このログだけでは確定できない。画像から手でbboxを作って当時のYOLO出力と見なすことはしない。上・横方向だけの接触か下辺の欠落かも未確定であり、接触判定を一括で無効化しない。

### 2. 背景からの姿勢推定が成立しない

全行`pose_reason=latest_scene_image_rejected`、`scene_initialized=false`。背景解析理由は以下。件数は各処理フレームへ保持された理由であり、独立した背景推定の試行回数ではない。

| 背景解析理由 | 処理ログ数 |
| --- | ---: |
| fewer_than_six_distinct_planes | 5,128 |
| insufficient_consensus | 269 |
| no_diverse_plane_pair_within_prior | 30 |

Sキーの保存画像を既存のOpenCV幾何処理で再解析すると、重複除外後の線由来の独立平面は3で、現行方式が要求する6に届かなかった（これは解析PCのOpenCV 4.5.5による再計算であり、GPU PCで当時記録された平面数ではない）。

コーン輪郭を直しても、この背景条件のままなら姿勢側で距離を保留する。6本条件を下げる、他の録画の姿勢を無条件に流用する、旧校正を検証なしで固定する、といった対応は行っていない。

## Sキーと終了記録

保存されたファイルは`decoded_f1f1b17f34a6447a9789291af128f991_f004903.png`で、対応する4903行目も存在する。Sキー保存は成功。生画像なので、数値やbboxが描かれていないこと自体は正常。

同フレームでは候補1、輪郭枠接触、背景姿勢不成立が記録されており、距離が表示されなかったことと整合する。

添付の`live_summary.json`は旧形式で、`worker_stopped=true`、`worker_error=null`はあるが、現行集計が要求する`runtime_status`と詳細`shutdown`がない。このため自動集計は`INCOMPLETE_CAPTURE`とする。ログの欠損や今回の通信障害を検出したという意味ではなく、厳密な終了確認に必要なメタデータが不足している。新形式の終了状態を捏造して書き足さない。

## 次の作業

追加録画を直ちに繰り返す前に、保存済み画像で以下を進める。

1. 同じチェックポイント・同じ推論条件で保存画像をオフライン再推論し、bbox・信頼度・接触した辺を記録する。推論環境が異なる場合は当時の出力そのものと同一とは扱わない。
2. 背景姿勢の自己推定が必要な現行条件と、実測した固定姿勢・床面基準を使う設計を区別する。現状の背景で自動姿勢が成立していないことは確認済み。根拠なくゲートを緩めて数値を出す方針は取らない。
