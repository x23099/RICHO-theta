# コーン下端の左右枠接触：二段階の観測範囲による限定的な安定化候補

作業日: 2026-10-30。**今回の赤コーン2枚で、下端候補が1/2枚から2/2枚へ増えた。検出枠の±1画素移動では、問題画像が3/9→7/9へ改善。過去の237枠と2133個の枠移動対照で、以前から取得できていた点の消失・位置変更は0。**

ただし、これは**既存画像で評価したオフライン候補**。床接地点・距離精度・走行安全の承認ではなく、既存のライブ距離処理には接続していない。フル動画での時系列安定性や新しい実カメラ試験も未実施。

## 問題と今回の変更範囲

前報の現session `15ae673c24484d119952ae391df611aa` では、ほぼ同じ静止状態にもかかわらず、frame1259の赤輪郭はbbox＋4 pxの左境界に触れて保留され、frame1655では下端(300,385)が得られた。単純な枠拡大は床・背景まで受け入れるおそれがあるため、本番の枠接触拒否を外さずに切り分けた。

新規実装: `src/cone_support_completion_candidate.py` の `observe_lateral_completion`。既存の色対応付きshadow抽出 `observe_separated_support` を先に実行する。

1. 既存shadowで取得済みの点・支持範囲・理由はそのまま返す。以前の成功点を新方式で置き換えない。
2. 元の結果が色輪郭の枠接触で、上部の固定seedから赤／黄が特定できているケースだけを調べる。通る色への切り替えや黄色から赤ステッカーへのfallbackはしない。
3. 最大の色領域がseedにつながる一つの領域であることを確認し、**左右の境界だけ**に触れている場合に限定する。上／下に触れた場合は対象外。
4. 上下は従来の4 pxのまま、左右だけ `p=clip(ceil(0.2×bbox幅),8,16)` pxと、その2倍へ広げた2範囲で再観測する。最大は左右32 pxまで。画像端や前方レンズの校正域を越える場合は切り詰めず拒否。
5. 両方で既存の輪郭・競合領域・下端支持範囲のガードを実行。seedにつながる領域が境界に触れず、**全画素集合と下端の結果が2範囲で完全に同じ**場合だけ残す。元のseed領域の画素が失われていないことも確認。
6. 新しく得る下端点は元の検出bbox内にあることを要求する。外なら保留する。

これは画像の欠損を埋める生成・補間ではない。**元画像に存在する画素を、より広い左右範囲で確認するだけ**。モルフォロジーで接地点を作る、目標距離から画素を逆算する、直線延長で下端を追加する処理はない。

2範囲は同じ画像の検査であり、独立した2回の撮影・物理検証ではない。閉じた赤領域が真の接地点と一致する保証もない。固定した範囲係数・上部seed自体は探索的な画像処理仮定で、距離精度から決めた値ではない。
