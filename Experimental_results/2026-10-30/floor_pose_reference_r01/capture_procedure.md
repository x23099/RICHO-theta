# 次に必要な画像：チェッカーボードを床へ平置き

作業日: 2026-10-30。床とカメラの向きを求めるための確認。内部校正の全面撮り直し・長い録画・走行・FFB試験ではない。

## 保存するもの

**現在のカメラとUSBキャプチャで受信した無注釈PNGを2枚。まず1枚だけでも解析を進められる。**

10/21に使った1マス20 mm、9×6内角の紙を平らな板へ貼ったものを使う。新しい印刷物はまだ不要。

1. カメラとKobukiを動かさず、静止させる。ROSの模擬ODOMやハンコンadapterは不要。
2. 板を白黒面が上になるように床へ平置きする。手で傾けて持たず、床に密着させる。ケーブルや物を下へ挟まない。カメラへ向けて立て掛けない。
3. カメラの前方約0.4～0.6 mを目安に置き、生映像の左の円・下半分に格子全体が見えるようにする。この距離は見やすさの目安で、正確な位置測定やメジャー合わせは不要。
4. 手を離して画面を確認し、GPU PCの「THETA static cone diagnostic」ウィンドウを選んで**Sキーを1回**押す。
5. カメラはそのままに、板だけを左右へ10～15 cm程度ずらし、床へ平置きしたままもう1回Sキーを押す。板の全体が左の円の中にあることを確認する。
6. 終了時はGPU側をQキー、送信側をCtrl+Cで終了する。

距離表示がWITHHELDのままでも、この画像保存は可能。既存のプログラムでSキー保存できるため、**撮影そのもののために今回の新規解析コードを各PCへ反映する必要はない**。

格子が小さく潰れる場合、板を持ち上げて大きく見せるのではなく、その状態の画像をまず提出する。検出や画素間隔をこちらで確認する。撮り直しや拡大印刷を先に繰り返す必要はない。

## 提出

受信側GPU PCの出力フォルダ内に保存される`decoded_...png`を2枚送る。生AVI、rosbag、長い録画アーカイブは不要。画面のスクリーンショット・BEV画像ではなく、Sキーが保存した1280×720のPNGをそのまま提出する。

加えて、床から白黒の印刷面までの厚さ（板＋紙）が分かればmmで教える。分からなくても、まず法線方向の検証は進める。板厚を未知のまま床高さの真値を得たとは扱わない。

## 映像送受信を閉じている場合の起動コマンド

すでに受信・送信できているなら再起動は不要。以下は閉じている場合だけ使う。出力フォルダは必ず新規名を使い、日付は実施日に合わせる。

### GPU PC：`hsr-Alienware-m16-R2`

以前の受信プログラムを終了してから実行する。モデルは以前照合したものを使う。

```bash
cd ~/yopi_ws/RICHO-theta
export THETA_DISTANCE_PYTHON="$PWD/yolo-env/bin/python3"
./start_cone_distance.sh receive --weights "$HOME/Downloads/cone_distance_v03.pt" --target-roi 270 0 350 720 --output-dir Experimental_results/2026-10-30/floor_board_capture_r01
```

`--target-roi`はコーン選択用であり、Sキー保存画像を切り抜く引数ではない。板は画像全体から後で解析する。比較ログフラグも今回の画像保存には必須でない。

### カメラ/Kobuki PC：`matunuc-NUC13ANHi5`

bird_eye.pyや他のカメラ使用アプリを終了してから実行する。

```bash
cd ~/theta_ws
export THETA_RTC_PYTHON="$PWD/theta-env/bin/python3"
bash src/start_theta_stream_rtc.sh --diagnostic --receiver-ip 150.89.169.78 --device 0 --fps 30 --capture-timeout-sec 3
```

映像専用経路。ROS domain、ODOM、ハンコンの設定は今回の保存には関係しない。新しい床姿勢候補を距離やFFBへ自動投入する機能は起動しない。
