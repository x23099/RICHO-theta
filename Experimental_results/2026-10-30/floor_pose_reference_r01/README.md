# 背景線を使わない床基準PnPの検証と、現在の床姿勢に不足する情報

作業日: 2026-10-30。保存データだけの計算・実装。実機、ネットワーク、ROS/TF配信、GPU推論、FFBは起動していない。

## 結論

**既知の床基準点から、背景の鉛直線を使わずにカメラ姿勢を求める処理を実装・検証した。**
ただし、過去の床基準から求めた姿勢を現在の映像へそのまま転用する根拠は得られなかった。

- 旧白紙の5校正点だけによるPnPはカメラ高さ58.48 cmを返し、独立に申告された実測59 cmと約5.22 mm差。
- 同じ録画内の未使用2点の平面位置RMSEは2.56 cm。
- 別録画の2.00 m点は2.3172 mになり、+31.72 cmの差。距離の近い別解を後から採用することもしない。
- 10/30の保存画像には既知寸法の床上マーカーが写っておらず、10/21のチェックボードは手持ち。床との相対姿勢を確定できる観測ではない。

不足しているのは、**現在のカメラ・キャプチャ出力で、床に平行と確認された既知寸法の平面の観測**。単に録画を増やす、背景線の必要本数を減らす、過去のTFを再設定することでは補わない。

ユーザーから「10/21の20 mm格子・板に貼ったチェッカーボードを今も使える」と回答を得た。[次の画像保存手順](capture_procedure.md)へ不足を限定した。長い録画や内部校正の全面撮り直しではなく、床に平置きした板の無注釈PNGをまず2枚（まず1枚でも可）確認する。

## 1. 処理の位置づけ

新規`src/floor_reference_pose.py`:

1. native1280×720の左レンズの対応点を既存のangular KB4モデルで視線へ戻す。
2. 正面半球内の視線だけを正規化ピンホール座標へ変換する。画像全体の変形・再保存はしない。
3. 既知の同一床面上の3D点と組み合わせ、OpenCV `solvePnPGeneric(..., SOLVEPNP_IPPE)`で平面姿勢の候補を得る。
4. 全平面解を保存。再投影誤差、点の正の奥行き、カメラの床側位置を記録するが、解を自動的に物理承認しない。

OpenCVの[公式PnP文書](https://docs.opencv.org/4.12.0/d5/d1f/calib3d_solvePnP.html)は、IPPEが4点以上の平面点を使い、複数解を返し得ることを説明している。コードはさらに重複・一直線の点・範囲外・非平面・正面半球外を拒否する。[魚眼の公式文書](https://docs.opencv.org/4.13.0/db/d58/group__calib3d__fisheye.html)にも魚眼点の正規化とPnPの関係があるが、今回は既存のangularモデルと角度領域を維持するため、既存`unproject()`を使用した。

従来のコーン測距が使う姿勢の初期化や背景6平面条件は変更していない。新しい姿勢候補を既存エンジンへ自動投入する接続も追加していない。`physical_metric_verified=false` / `usable_for_ffb=false` / `published_to_ros=false`を維持する。

## 2. 既存床基準による6自由度の対照

入力は`2026-10-21/angular_metric_validation_r01/results_r01/floor_reference_results.csv`の既存の読取点とユーザー申告座標。
元の内部K/Dは固定。高さ59 cm、XY=0を制約として与えず、回転・並進を同時に求めた。コーン距離をfitへ渡していない。

- 校正用: C080 / C130 / C200 / L130 / R130の5点。
- 評価専用: 同一録画H100 / H160の2点、別録画10/19の2 m点。
- target軸はx前方・y左・z上。元の左右参照値は右正なのでyへ変換するとき符号を反転。
- 白紙の読取点と設置座標は、独立測量で検証済みとまでは扱っていない。

| 項目 | 解0 | 解1 |
| --- | ---: | ---: |
| 校正5点の再投影RMS | 0.6563 px | 14.3220 px |
| 推定カメラ高さ | 0.5848 m | 0.4590 m |
| 推定カメラ前方位置（紙原点基準） | −0.0287 m | +2.5909 m |
| 未使用2点の平面位置RMSE | 0.02563 m | 0.05628 m |
| 別録画2 m点の前後位置 | 2.3172 m | 1.8647 m |

解0は旧録画の内部整合性を示す候補であり、現在の床姿勢の検証結果ではない。
解1の別録画の距離が2 mへ近いという理由で解を選ぶと、評価距離を選択へ漏洩させる。独立の高さ59 cm・紙原点とカメラ直下の関係や、校正再投影とも整合しないので、そのような採用はしない。

同じ旧点への従来の「高さ59 cm固定・回転3自由度fit」は未使用2点RMSE2.17 cm、別録画2 mは2.248 mだった。今回の自由度追加で転用の問題が解消したとは言えない。自由度・方式の最良値だけを選ばず、全候補を保存した。

結果: [全候補と来歴](evaluation_r01/summary.json)、[全点・全候補の結果](evaluation_r01/point_evaluation.csv)。

## 3. 既存チェックボードを床姿勢へ流用しなかった理由

10/21 r03の`target_review.json`は対象を手持ち板と記録している。対応する元frame2771を新しい処理で調べると、54内角、格子間隔中央値11.965 pxを検出できた。
しかし床へ平置きされたという確認がないため、**床姿勢を1件も出さない**ことを確認した。

また10/30の現在の保存frame4903では、チェッカーボードを検出せず、姿勢候補は0。背景の机・コーンを既知の床基準へ勝手に置き換えていない。

- [手持ち板の負の対照](handheld_board_control_r01/floor_board_report.json)
- [現在画像のマーカーなし対照](no_board_control_r01/floor_board_report.json)

内部校正に使う板の各画像の姿勢は、板自身の座標とカメラとの関係。板と床の関係が未知なら、その姿勢を床・車体TFとして扱えない。カメラの取付を変えていないという申告も尊重しつつ、この不足を別の情報として扱う。

## 4. 床板画像を受け取る処理

新規`src/diagnose_floor_board_pose.py`は、保存済みPNGを入力にするだけのオフライン処理。

- 前方左レンズ・下半分の明示的な範囲を使い、窓の固定チェック模様を使わない。
- 既存と同じ9×6内角、実測20 mmの板を使用。部分格子を補完して54点へ増やすことはしない。
- `--board-on-floor`がない場合、板を検出できても床姿勢を出さない。この引数は人による設置確認であって、画像だけで平面接地を証明するものではない。
- 平面解を両方保存し、板座標の任意の向きとは別に法線の符号をカメラ側へそろえる。車体の前後/yawを推定したことにはしない。
- 板の厚さが不明な場合、床ではなく印刷面までの高さとして記録。厚さを実測して渡した場合だけ、床との差を別項目へ加算する。
- 現在の20 mm板が魚眼の床画像で小さすぎる可能性もある。格子間隔を記録し、既存内部校正の8 px基準を満たさない場合は明示した診断候補にとどめる。元の校正基準を変更していない。

**床平面の法線が得られることと、車体前後方向・光学中心と車体中心の位置・コーン実接地点・距離精度が検証済みであることは別。** 現時点で走行・FFBへの接続や`base_link` TF配信を追加しない。
