# 対象色対応付きの輪郭抽出候補と比較ログ専用モード

作業日: 2026-10-30。追加撮影なし。保存画像・保存済み検出枠のみで検証。実カメラ、GPU推論、通信、ROS、FFBは起動していない。

## できるようになったこと

**コーン上部の色から対象色を先に決め、赤・黄色を別々に扱う抽出候補を実装した。採否がよい色を後から選ぶ処理ではない。**

ただし新方式はまだ比較ログ専用。従来方式の観測・時系列品質・姿勢・鮮度・距離判定に置き換えていない。

- 今回の赤コーンは赤として対応付け、床・背景の黄色成分を混ぜずに下端候補を得られる。
- 黄色コーンは引き続き黄色として扱う。同じ色の床へ連結した場合は、従来と同じ輪郭端接触の条件で保留する。赤い小部分へ切り替えて通すことはしない。
- 上部の色が少ない・曖昧・画像外・反対レンズなら保留する。別の色やbbox下端で穴埋めしない。
- 新方式の下端が得られても、背景姿勢が得られなければ距離は保留のまま。FFBへ使用する権限はない。

前段の原因解析: [保存画像監査](../cone_saved_frame_audit_r01/README.md)。

候補の色根拠はYOLO bboxの中央幅10%、高さ20～40%の領域。色付き画素20以上、赤または黄の占有率90%以上を要求する。これらは**未確定の試作条件**であり、接地や正しいコーン形状を証明するものではない。今回の結果へ合うように値を再調整していない。

選択した色の最大輪郭には、元と同じ面積20、競合輪郭25%、枠端接触、最小広がり、支持範囲と下端点の対応の条件を適用する。さらに、下端点の連結成分が上部の色根拠とつながっていることを要求する。輪郭条件を通る別色へフォールバックしない。

既定の元処理が使う赤+黄マスクは変えていない。共通関数へ移動した元処理は、凍結コードとの比較で全233枠一致した。

### 比較ログの意味

明示的に有効化した場合だけ、`distance_frames.jsonl`へ次を追加する。

- `selected_detector_boxes`: 当該frameで選択した実YOLO枠と信頼度。次回から未保存のbboxを推測する必要がなくなる。
- `colour_support_shadow.candidate`: 対象色、色の根拠となる画素数、seed範囲、保留理由、実観測支持列と候補点。
- `controlling_distance=false` / `usable_for_ffb=false`: 候補の合否は距離判定へ入らない。

候補処理の例外は比較項目のエラーとして記録し、従来の検出失敗へ誤変換しない。ただし比較処理にもCPU時間はかかる。**実際の経過時間を偽らず、追加処理で500 msを超えた場合も元の鮮度条件は適用する**。有効化した実機での追加負荷は未測定。

### 母集団と出典の制限

- 元の固定間隔画像は492枚。そのうち保存検出と同一frame・時刻・録画hashが対応するのは176枚。残り316枚を「コーンなし」とはせず、検出根拠不足として今回のモデル枠比較へ含めていない。
- 176枚では複数コーンの枠があり、反対レンズ・低信頼度などを元と同じ選択で除いた後、206枠を個別に比較した。この個別比較は、実行時の複数候補保留を解除した意味ではない。
- 人手枠は`datasets/cone/ab_bootstrap_v01`の画像・ラベルhashとレビューの対応を照合した。色の独立した正解ラベル・床接点ラベルのあるデータセットとして扱っていない。

- 学習・新しいYOLO推論・距離ラベルを用いたfitは今回実施していない。
