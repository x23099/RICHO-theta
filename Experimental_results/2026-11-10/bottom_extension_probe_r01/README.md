## 実装と条件

[probe.py](probe.py) はこの実験フォルダ内のオフライン専用処理。liveからimportせず、rootに測距用`point`を返すobserverとしても使わない。

1. 現行`observe_upper_completion`を元画像で実行し、受理済みの観察はそのまま維持する。
2. 元の上下左右4px探索で、seedにつながる色成分が**下端だけ**に触れる場合を対象にする。混色・未検出・左右／上端との複合接触は対象外。
3. 上端・左右は4pxのまま、下側だけ `p=clip(ceil(0.2×bbox高さ),8,16)` と `2p` の有限2段へ広げる。native画像・校正領域の外へclampしない。
4. seed、赤／黄の選択、HSV条件、既存の競合輪郭・支持点品質を維持する。2段で閉じた色成分のpixel hashと支持範囲・点が一致することを要求。
5. 閉じるだけの候補は `closure_only_point_NOT_safe` へ記録する。これは採用点ではない。
6. 条件付き案では、元のseed成分の画素を全て保持し、**元cropで観察した中央下辺の全列が変わらず、選択点も既にその下辺に存在し、元の小数bbox内にある**ことを追加で要求する。

支持点のclampや選び直し、bboxの丸め緩和、過去frameとの補間、未観測の下辺の外挿は行わない。前段のbbox境界案と同時に緩めず、変更要因を分離した。条件付き候補にも物理接地・実距離精度・制御用途の承認は与えない。

## 合成反例と条件の効果

1280×720の合成画素をメモリ内で作成。カメラ画像を加工したものではなく、実写画像として保存していない。三角形の描画上の下辺はY=400。

|合成条件|閉じるだけで選ぶ点|下辺維持を加えた案|意味|
|---|---|---|---|
|cropで下端が切れた三角形|[320,400]|保留|新しく見えた下辺なので、元の観察下辺維持条件は満たさない|
|中心付近にY=408までつながる有限の色領域|[320,408]|保留|2段で閉じても、追加の色領域の先端を選べてしまう反例|
|中央下辺の外側にだけ伸びる細い色領域|[320,400]|比較用候補|元の中央下辺・点は変わらず、bbox内にも残るケース|
|Y=480まで続く色領域|なし|保留|上限32px以内で閉じず、無制限に探索しない|

有限色領域は反射・同色物体の連結を想定した**合成反例**であり、今回の実走行15件の原因が反射だったと証明したものではない。描画上の8px差を実測誤差cmへ換算しない。

## 判断と限界

- **単純な下側拡張は見送る。** 2段階で輪郭が閉じることだけでは反例を除けない。
- 元の下辺・点を保持する条件付き案は、オフライン比較器として残す。合成では限定ケースを切り分けられたが、元の実検出枠10枚での改善件数は0なので本番採用の根拠にはしない。
- 現在の走行測距は、今回の録画対応区間で確認した約29.9件/秒・数値549/569件の構成を維持する。この追加実験を「改善後96.5%」や「全保留を解決した」と表現しない。
- 今回の15件へこの案を評価するために不足しているのは、そのframeの**未展開1280×720の元画素**。追加のコーン寸法・床の測量・チェッカーボード撮り直しではない。運転UI録画をnativeへ逆変換して代用しない。
- 今回は追加撮影を求めない。実画像の正解ラベル付き負例がないため、実FPR・実測誤差の改善も認定しない。これ以上のnative画素依存評価は、その入力がない限り未検証として区別する。
