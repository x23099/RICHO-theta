# 台座が見える場合の保留を減らす統合候補（下端半画素＋自己領域棄却）

2026-11-10。**「天板付近を除外する」ことと「元bbox下端だけの0.5px以内の不足を許す」ことを一つのオフライン比較にまとめた。** 保存画像8枚では天板に隠れた5枚を保留し、台座が見える14922の候補値を維持する。ログ上では、天板境界から離れた19保留すべてが、この狭い条件に一致した。

新しい点を補間・予測したり、距離値を調整したりはしない。**live測距の判定・操縦は未変更、GPU PCへ未反映。** 元画像で確認できる範囲とログ条件だけの比較を明確に分ける。

## 統合した条件

実装: [cone_guarded_lower_edge_shadow.py](../../../src/cone_guarded_lower_edge_shadow.py)。既存の輪郭・空間支持条件と [自己領域棄却](../self_body_boundary_shadow_r01/README.md) を再利用する。

1. 現行baselineを元のまま別欄に保持する。baselineの有効点も自己領域棄却の比較対象にするが、元記録を書き換えない。
2. baselineが保留した場合、既存のseed付き輪郭が2段階の拡張先で同一・閉鎖し、既存画素とsupport条件を維持した場合だけ候補を得る。
3. 候補点は**左右と上端について元float bbox内**でなければならない。許すのは `y2 < 観測点y <= y2 + 0.5` だけ。外向き整数丸めへのfallbackはしない。
4. 候補support全列が、同sessionの確認済み参照天板境界より余白分上にあることを要求する。session／参照PNG hash未確認・範囲外・境界付近は保留。
5. 通った場合も元の観測point／supportを使う。計算式・校正は以前と同じで、床接地や制御への使用許可は付けない。

0.5pxは今回比較している固定の画素重なり仮説であり、YOLOの枠が物理的に0.5px正確だという主張ではない。元bbox・元画像を変更せず、左右や上端の緩和まで広げない最小範囲に限定した。

## 到達点と残る条件

ここまでで、見える台座に対する保留を減らすための**一つの統合比較候補**と、既存ログ上の影響範囲を整理できた。単純なbbox丸め、下側の無制限拡張、過去値保持をliveへ追加していない。

実機の正式表示へ適用する前には、少なくとも次を区別する必要がある。

- 天板参照はframe14604から読んだ同session専用の仮説。新sessionへ無条件転用しない。通常の受信画像で参照が現在の天板と対応するか確認する経路が必要で、再校正や新しい寸法測定とは別問題。
- 原画像が確認できない18候補の条件一致は、実際の接地や精度の証明ではない。
- 人や他物体の遮蔽、カメラ／天板の相対位置変化、姿勢変動は今回の天板境界だけでは解決しない。

次の実装段階は、正式な距離表示・操縦に接続せず、同session参照を明示した**比較専用出力**へこの統合候補を通せるようにする準備。実機への反映・新たな収集が必要になった場合は、その対象に限定して相談する。今回追加撮影は要求せず、Git commit/pushも行っていない。
