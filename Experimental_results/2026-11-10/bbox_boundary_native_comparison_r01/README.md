2026-11-10。**元画素が残る過去10枚で比較器を実行し、現行の数値3件と保留7件を全て維持した。** 別に、同じ実画像2枚のbbox下端だけを操作する12条件を作り、座標境界を変えると元の観察点を動かさず追加候補を得られることを確認した。これは実走行での改善実績・誤検出率の認定ではない。

正式結果は [results_r02/summary.json](results_r02/summary.json)、[元の保存検出枠20比較行](results_r02/metrics.csv)、[bboxだけを操作した24比較行](results_r02/controlled_bbox_jitter.csv)。r01はbbox感度比較を加える前の履歴。

## 変更範囲

- [src/cone_bbox_boundary_shadow.py](../../../src/cone_bbox_boundary_shadow.py) を追加。オフライン専用で、liveのimport・起動引数・設定には接続しない。
- 元画像に対して現行`observe_upper_completion`を実行した後、現行受理は辞書も値もそのまま別の比較欄へ複製する。
- 新規候補に入るのは、横側補完で同じ閉じた成分と支持範囲が2段のcropで得られ、最後の小数bbox条件だけで拒否された場合のみ。
- 比較する定義は画素セル±0.5pxの重なりと、bboxの外向き整数化・端を含む定義。前段の[ログ監査](../support_boundary_audit_r01/README.md)と同じ、明示的な別条件。
- 支持点をbbox端へclampしない。下側／上側への新規拡張、混色の再選択、閾値調整、前frameの点の保持、距離の補間はしない。
- `diagnostic_only=true`、`live_authorized=false`。制御・FFB・接地・物理精度の承認は与えない。

比較器自身はnative画像上の現在frameの輪郭を使う。今回の走行20frameにはnative画像がないため、この比較を今回の20件を再計算した結果とは表現しない。

## 1. 元の検出枠を使った過去10枚の比較

11/9・11/10の保存枠再生検証と同じb559 session 8枚、df33 session 2枚。元PNGのSHAを過去の来歴と照合し、元の保存YOLO枠を使った。YOLOの再推論や実機は起動していない。raw画像と復号画素のhashを前後で照合し、無加工・1280×720のまま利用した。

|条件|距離あり|保留|既存数値の変更|
|---|---:|---:|---:|
|現行|3|7|—|
|半画素の重なり候補|3|7|0|
|外向き整数化候補|3|7|0|

維持した距離は1.006457373m、0.979062890m、1.954425695m。これは校正転用精度の再認定ではなく、比較処理による既存値の変更がないことを確認する回帰検査。

7保留のうち、横側補完の最終bbox条件で拒否されていた2枚は以下。いずれも1pxを超えており、今回の境界条件では救済しなかった。その他は上側補完のbbox条件や未閉輪郭等で、この比較器の対象外。

|過去のframe|保存された候補Y|元bboxのy2|はみ出し|
|---|---:|---:|---:|
|b559 f033066|419|417.369232|1.630768px|
|b559 f036478|419|417.424011|1.575989px|

**元の10画像・元の検出枠では、今回の改善候補による出力増加はなかった。** この画像群はコーンを含む検証画像であり、背景だけ等の正解ラベル付き負例集ではない。「実画像で誤検出率が0になった」とは主張しない。

## 2. 元画像を変えず、検出枠の境界だけを操作

上記2枚の元画素・色・床モデルを維持し、bboxのy2だけを、保存された観察点Yに対し−1.1／−0.75／−0.5／−0.25／0／＋0.25pxへ置いた。2枚×6条件＝12条件、2比較定義＝24行。

これは検出枠の座標への感度を切り分ける**人工条件**であり、新しい実検出枠でも、今回の走行中の画像でも、物体を移動させた実験でもない。

|12人工条件の観察点出力|現行|半画素の重なり|外向き整数化|
|---|---:|---:|---:|
|点が得られた条件|4|8|10|
|現行より増えた条件|—|4|6|
|点の座標自体が変わった条件|—|0|0|

この範囲では、画素の観察点は同じなのにbboxの小数下端が変わるだけで判定が切り替わることを再現した。1.1px外の条件は両案とも保留。結果を「実際の検出率が倍になった」「実測誤差が改善した」と解釈しない。

## 3. 合成画素による拒否条件の検証

新規15テスト成功。赤／黄の既存受理をそのまま維持し、半画素と整数化が異なる結果になること、1px超を救済しないことを確認した。

下側へつながる色領域、まだ閉じない横側背景、競合輪郭、混色seed、空画像、上側だけの失敗は、新しい候補で受理しなかった。入力画素・bbox・元の観察辞書の不変、画像寸法、不正入力、承認flag、live entry pointから未使用であることも検査した。

これらは境界条件の実装テストであり、実際の反射や未知物体に対する誤検出の一般保証ではない。正式な実画像の負例正解は未受領のため、実FPR等は計算しない。

## 採用判断

**liveには未採用。オフライン比較器として採用した。** 理由は、既存受理を維持し、人工条件で候補の働きを確認できた一方、元の実検出枠の10枚では改善件数0、今回の走行5候補の元画素での照合は未実施だからである。

比較を続ける場合は、影響範囲が小さい半画素案を先に評価し、件数が増えるという理由で整数化案を選ばない。前段ログでは走行区間の候補が3件対5件、全runの候補が733件対5,172件であり、両案の影響範囲が大きく異なる。

走行測距そのものを止めたり、追加の校正撮影へ戻す必要はない。現在の走行経路・表示・記録は維持する。残る下端15件も今回の案では解決しないため、この比較を全20件の解決とは扱わない。
