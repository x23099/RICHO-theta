# 床接地点方式による障害物位置推定の実装・評価

## 結論

青箱の輪郭全体をBEVの床面へ投影して最近点を取る従来方式から、元の魚眼画像上で障害物の床との接地点候補を選び、カメラ光線と床平面の交点を求める方式へ変更した。

最新の標準化済み校正データ10地点で横方向だけを校正し、独立したホールドアウト4地点で評価した結果、検出率100%、平均位置誤差2.3 cm、最大位置誤差4.0 cmとなり、事前に定めた合格条件（平均5 cm以下かつ最大8 cm以下）を満たした。

## 修正の理由

従来のBEVは床面の見え方を作る用途であり、垂直に立つ箱の表面全体を床平面と仮定して投影すると、箱の高さと画像内の見え方によって接地点が車体側へ引き寄せられる。平面変換は同一平面上の点に対して成立するという前提があるため、距離・相対速度・TTCへ使う位置は、物体表面全体ではなく床との接地点から求める必要がある。

参考: [OpenCV: Basic concepts of the homography explained with code](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)

## 実装

- `src/ground_contact.py`
  - 元画像の魚眼画素を車体座標系の3次元光線へ逆投影する。
  - 下向きの光線と高さ0 mの床平面との交点を計算する。
  - 輪郭中の近い側8%の中央値を床接地点とする。
  - 青色抽出は今回の実験用アダプターとして分離し、将来は別のセグメンテーション結果を同じ幾何計算へ入力できる構成とした。
- `src/bird_eye.py`
  - 既定の位置推定方式を `ground_contact` に変更した。
  - 推定位置、追跡位置、BEVマーカー、CAL/NEAR/FAR/SIDE判定を新座標へ接続した。
  - 従来方式は設定を切り替えた場合の比較用として残した。
- `src/evaluate_ground_contact.py`
  - Qt画面、カメラ、PyTorch、YOLOを使わず、録画済み `raw.avi` と `metadata.json` だけで校正・評価できるCLIを追加した。
- `tests/test_ground_contact.py`
  - 魚眼投影の往復、床交点の距離復元、録画名の正解座標解析、横方向校正を自動試験する。

## 採用したモデル

前後方向 `z` は光線と床平面の交点をそのまま使用し、経験的な倍率・切片は加えない。横方向 `x` だけ、カメラ取付けとレンズ中心の残差を補う一次式を使用する。

| 項目 | 値 |
|---|---:|
| x倍率 | 0.6076887419 |
| x切片 | +0.0225957279 m |
| z倍率 | 1.0 |
| z切片 | 0.0 m |
| 接地点候補割合 | 0.08 |
| 元画像輪郭の最小面積 | 300 px |

## 過学習に対する確認

接地点候補割合を0.01～0.30へ変更しても、最新ホールドアウトはすべて合格条件内だった。したがって、0.08という単一点だけに結果が依存している状態ではない。

一方、過去の録画をすべて混ぜたセッション横断評価には、当時の設置距離・基準点・カメラ状態の差が含まれ、同じ精度にはならなかった。正式判定は条件を統一して最後に撮影した独立4地点とし、過去録画は回帰確認用に限定する。今後カメラ取付けを変更した場合は、同じ標準化手順で再校正・再ホールドアウト試験を行う。
