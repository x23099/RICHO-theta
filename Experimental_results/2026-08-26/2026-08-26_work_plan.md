## 5. 実行手順

### 5.1 preflight

KobukiとODOMを起動後、リポジトリ直下で実行する。

```bash
python3 src/preflight_field_experiment.py \
  --config src/bird_eye_config_raw_ground_distance.json \
  --record-dir recordings/2026-08-26_raw_ground_distance_holdout \
  --camera-device 0 \
  --camera-fps 30 \
  --camera-frames 60 \
  --odom-topic /odom \
  --require-clean-git
```

`Experiment config`に`area_mode=raw_ground_distance`、`normalized_area_min=2000`が表示され、
Cameraが約30 fps、ROS odometryがPASS、総合判定がPASSであることを確認する。

### 5.2 アプリ起動

```bash
python3 src/bird_eye.py \
  --device 0 \
  --camera-fps 30 \
  --config src/bird_eye_config_raw_ground_distance.json \
  --record-dir recordings/2026-08-26_raw_ground_distance_holdout \
  --experiment-label pilot_odom \
  --odom-topic /odom
```

最初の5秒録画はholdoutへ含めない。pilotでODOM記録を確認できなければ、本試験を開始せず、
アプリの起動引数、ROS環境、topic名を修正してpilotからやり直す。

## 6. 事前固定の判定条件

候補は次をすべて満たした場合だけPASSとする。

- 青箱あり4静止試行で、検出率、観測採用率、追跡率が各98%以上。
- 青箱なしで生検出、追跡、警告が発生しない。
- 遮蔽の安定表示区間で観測採用率98%以上。
- 遮蔽中の位置外れ値棄却率95%以上、最大`abs(vz)` 0.30 m/s以下。
- 2/2遮蔽イベントで追跡が失効し、2/2で再捕捉する。
- 全6試行で実効FPSが30 fpsの±1%以内、フレーム欠番なし、時刻列が単調時計と一致する。
- 全6試行でODOM有効率100%。

### PASS時

1. `src/bird_eye_config.json`の方式と面積しきい値だけを候補値へ変更する。
2. 単体テストとpreflight設定検査を実行する。
3. 既存のP0-A位置、P0-B遮蔽、P0-C動的録画を再生し、回帰の有無を確認する。
4. 実機holdout結果と本番設定変更を別コミットにする。

### FAIL時

1. 本番設定を変更しない。
2. 不合格条件を、検出生値、面積正規化、NIS、校正範囲、追跡のどこで失敗したか分類する。
3. このholdoutを診断用へ移し、同じ録画でしきい値を調整して採用判定をやり直さない。
