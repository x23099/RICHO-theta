# 10/23：上下を独立抽出する姿勢候補の比較

## 到達点

**上側の元候補を維持したまま下側の候補を平面段階で追加し、元の採用27画像を全て保持できた。**
採用画像は27→53、録画ごとの時間再現性は1/9→5/9となった。
前回の単一ROI拡張では失っていた紙・コーン同一姿勢系列も、今回は前半9・後半8画像のまま残った。

ただし、追加採用26画像は全て**上側5本＋下側1本**の支持で、下側単独の姿勢取得は0画像。
上下それぞれで独立した姿勢を得て一致する、という強い確認は0件である。
**距離の高精度化・真の鉛直の確認・本番FFBの成功を示す結果ではない。**

日付整理により、これまで10/22として保存した作業も[10/23日報](../../../Daily_reports/2026-10-23_daily_report.md)へまとめた。
旧フォルダ・録画・hashは変更していない。本日の新しい結果だけをこの10/23フォルダへ保存した。

## 固定した比較

[実行前条件](method.md)に沿い、全9録画492画像と元の時間分割、K/D、prior、6平面/角度/SVD条件を保持した。

| 系列 | 処理 |
|---|---|
| upper | 元のx=40..600, y=60..300。凍結採用平面を元順序で再利用 |
| lower | x=40..600, y=301..430。画素の投票/支持集合を上側と分離 |
| late_fusion | 上側を全て元順序で保持し、下側は既存方向と2度未満なら追加せず、重複以外を追加 |
| independent_agreement | 両帯がそれぞれ独立に姿勢条件を満たし、方向差2度以内のときのみ上側方向を保持 |

画像は1280×720の全画角PNGを読み込むだけで、切り抜いた画像や加工画像を保存していない。
計算へ使う座標集合だけを分けた。上下別抽出ではHoughの上限200候補が帯ごとに適用されるので、
単一ROI拡張と投票予算まで同じではない。

18固定代表で新抽出器のupperが元の画素・normal・採否まで一致し、全492画像のupper姿勢も元結果と一致した。
下側を追加しても上側の投票集合・支持点・順序は変わらない。
上下に跨る近い法線を二重に数えないよう、213件の下側候補を統合時に見送った。
この法線の重複排除は、同一物理線や測量された独立線の認定ではない。

## 支持の内訳と限界

統合の採用53画像のinlier内訳は、上6＋下0が24画像、上6＋下1が3画像、上5＋下1が26画像。
元の採用から新たに増えた26画像は全て最後の組合せで、下側の1方向が可否を左右している。
下側単独の入力平面数は0～6本で、6本ある5画像も姿勢条件を通らなかった。
したがって、上下双方で独立に同じ方向を測ったと説明することはできない。

下側は幅の狭い帯で、支持長・視線角の条件にも不利。そこにコーン・人・床などが入る場合もある。
元のupper入力を保てるという実装上の性質と、統合後の方向が物理的に正しいことは別である。
本データで元採用27件を失わなかったことは、全入力で絶対に回帰しない数学的保証ではない。
追加候補によって最大consensusや再計算が変わる可能性は引き続きある。

建物線の真の鉛直性・床水平・高さ/heading・校正と撮影状態の対応・実接地点の課題は未解決。
新しい方向を距離計算へ適用する処理、TF行列の出力、FFB送信は作っていない。
全出力`usable_for_ffb=false`で本番`src/`や設定は変更していない。
