# 10/23継続：上下の連続輪郭を1票として扱う対照

## 結論

**連続する上下支持を1票として扱う処理を実装し、二重票を作らないことを確認したが、適用できる録画は増えなかった。**
票数だけをまとめる対照は前回と同じ28画像採用、支持点を連結して法線も再計算すると24画像採用。
時間再現性を通るのは全系列で同じ1録画だった。

再計算では元の上側採用27画像のうち4画像を見送るようになった。
採用数が減ったことだけで精度が悪化したとは断定できないが、適用範囲や距離精度が改善した根拠も得ていない。
本番の設定/姿勢/距離/TF/FFBへは反映せず、**この連結案の比較はいったん完了**とする。

## 固定条件

[実行前条件](method.md)に沿い、同じ9録画492画像とK/D・prior・必要6平面・consensus/SVD・時間判定を保持した。
前回と同じ保存コーン枠を使える176画像で、実観測画素の対象除外を維持した。
残る316画像は保存予測がなく全系列で保留する。新規YOLO推論・GPU/実機操作はしていない。

画像はnative1280×720のまま読み、計算する座標集合を扱うだけ。加工画像・補間点・人工エッジを追加しない。
距離の正解値・コーン寸法を候補選択へ入れていない。
開発データを見た後の原因対照であり、独立した新環境評価ではない。

### 上側群の復元と曖昧さ

元の上側重複除去を縦span降順、法線2度未満、最初の保持候補優先で再生し、
捨てた候補がどの元代表に属したかを復元した。元採否が一致しない場合は停止する。
代表が対象枠除外で失われた群は復活させない。

下側始点と上側終点の縦gap1～6 px・横差6 px以内の場合だけ実支持点を上→下の順で連結し、
元と同じ視線平面条件へ再入力した。RMS0.15度、最大0.4度等の条件は変更していない。

複数の上側群へつながる、または同じ群へ複数の下側がつながる場合は、
都合のよい方を選ばず下側を保留する。同じ1群内で複数の支持候補がある場合だけ、
RMS→最大残差→支持点数降順→候補IDの固定順で選ぶ。

**画像上の連続可能性や元の法線群は、物理的同一線や建物の鉛直を認定した意味ではない。**
元の群には近い別の物理輪郭が含まれる可能性もあり、代表から別の支持へ替えることには限界がある。

## この比較の終了判断と次の範囲

今回、支持点の連結・1票化だけで姿勢推定の適用範囲を広げる根拠は得られなかった。
ここでさらにROI・必要本数・角度を試して採用数を増やす作業は続けない。
連結再計算案を本番へ導入せず、元の成功/失敗と比較結果を凍結する。

追加撮影なしで続けるなら、測距を有効と扱える入力・校正・姿勢・観測品質の条件を整理し、
不足した録画を理由付きで保留する回帰評価が次の範囲となる。
実測していない姿勢や接地点を仮定して本番へ渡すことはしない。現在、新規録画を求める必要はない。
