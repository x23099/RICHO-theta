# 主測距を維持し、追加比較だけの頻度を制限する実験

2026-11-11。compact後も比較ONは26.54件/秒、主P95=45.22ms。主測距はそのままに、検証用比較だけを明示的に上限10Hzへ抑える候補を検討する。既定は無制限（0）で過去動作を維持し、10Hzを正式最適値とは呼ばない。

1. 保存r03の時刻・比較行と一定30Hzの8画像反復で0/5/10/15Hzを模擬する。選択数、元画像別の偏り、数値候補の非選択、選択間隔を記録。再生時刻が変わる実GPUでの効果とは区別する。
2. 制限は比較worker内だけへ追加。全採用frameでadmit・入力鮮度・session／gap・pin/load/失効を確認し、重い幾何比較だけを制限する。pin／要求処理を頻度制限で止めない。producerの主測距／pipe後tapへ待機やコピーを追加しない。
3. 比較しないframeも同じIDで `comparison_rate_limited` の非数値行を記録し、前回の比較距離を現在値として残さない。skip数・実評価数・上限をstatusに明示する。0.5秒の鮮度を緩めず、load直後は初回評価可能にする。
4. CLIは明示的な比較dirを必要とし、既定0を維持。受信／driver子／保存画像CUDA試験へ同じ設定を渡す。新設定が無効なときは黙って既定値へ戻さない。
5. 関連回帰・制限あり／なしの実thread試験・保存主行不変・選択行の比較値再現・skip時の非保持・gap/session/例外/終了をローカル検証する。比較数値の件数減少を失敗や精度悪化と即断しないが、間引きによる検査機会の減少は明示する。
6. 合格した変更だけをGPU PCへ渡し、保存画像で上限10Hzを明示した実CUDA試験を新規r04へ保存する。カメラ／matunuc／ROS／走行・新規撮影は不要。物理精度・実カメラ遅延・制御許可は付与しない。commit/push・実機操作は今回行わない。

## シミュレーション後の判断：単純間引きは実装しない

r03の保存worker開始時刻へ10Hz制限を模擬すると、320行中97行を選ぶ一方、元の40数値機会は1行しか残らなかった。一定30Hzの8画像反復でも、5Hz／15Hzでは位相により元14922を全て外した。これは短時間対象の検査機会減少と反復標本の位相偏りを示し、実カメラの見逃し率ではない。前述の頻度制限実装・GPU r04案は採用しない。実行頻度・runtimeは変更しない。

代わりに、既存profileで大きいangular unprojectの呼出しを監査した。画像領域内かのboolだけを使う箇所でも64回の逆算を実行していた。`guarded_domain_only_r01` で、同じ有効域条件だけを計算する関数に分ける。実際に必要なrayの64回逆算はそのまま残し、間引きや観測の使い回しを行わない。
