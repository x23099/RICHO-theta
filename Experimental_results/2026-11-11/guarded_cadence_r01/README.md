# 単純な比較頻度制限は今回は採用しない

2026-11-11。GPU r03の保存比較ログの時刻を使い、5／10／15Hzの単純な開始間隔制限でどの入力を選ぶかだけを試算した。実装・実CUDA再計算・実時間性能の測定ではない。

| 時刻条件・頻度 | block 1 選択／数値機会 | block 2 選択／数値機会 |
|---|---:|---:|
| 保存時刻・制限なし | 160／20 | 160／20 |
| 保存時刻・10Hz | 49／1 | 48／0 |
| 均一30Hz仮定・10Hz | 54／7 | 54／7 |
| 均一30Hz仮定・15Hz | 80／0 | 80／0 |

同じ8画像の反復と選択位相に依存し、40数値は元14922の反復である。10Hzにした実カメラの検出率・誤差を意味しない。また処理量を変えると開始時刻自体も変わるため、保存時刻の選択結果を実装後の速度・鮮度の予測とはしない。ただし単純な間引きが利用可能な比較機会を落とし得る具体例にはなる。

今回は頻度制限を実装せず、[不要なray逆算の削減](../guarded_domain_only_r01/README.md)へ進んだ。主測距・比較workerの周期、500ms鮮度条件、棄却条件は維持する。

根拠：`simulate.py`、`simulation_r01/summary.json`・`selection.csv`。入力SHAはJSONに記録。選択処理の3テストはdomain-only側の404テストに含めて成功。新たなGPU試験・撮影はこの間引き案のためには不要。
