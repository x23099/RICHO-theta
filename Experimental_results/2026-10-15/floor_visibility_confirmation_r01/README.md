# 遠方V字先端の視認限界：ユーザー確認

2026-10-15。ユーザー回答：

> 1.3まではかろうじてわかるが、それ以上遠くなるとV字の先端を認識するのは厳しい。形が潰れてほとんどまるっぽくなっている

確認対象は以前の床frame187と今回の床frame141の中央1.30/2.00m。
回答は録画ごとに分かれていないので、個々の画像pixelが人により承認されたとは扱わない。

## 判断の確定範囲

- 遠方のV先端は、物理的な基準点に対応する画像位置を信頼して特定できない。
  既存のassistant候補を校正・精度評価の確定GTへ昇格しない。
- 1.30mも「かろうじて見える」段階。±2px等の読取り精度が確認されたわけではない。
- 近方0.80/1.00mや左右点を、この回答だけで個別承認済みにしない。
- 今回確定したのは**遠方の基準点が不十分であること**。距離のずれの原因全体が
  読取り誤差だけだった、機械固定が悪かった、魚眼モデルが間違っていた、とは確定しない。
- 以前のcentre2等のfit結果は、不確かなpixel候補に対する説明力を調べた探索記録として残す。
  候補自体・過去の結果・元画像を上書きせず、本番採用しない判断を維持する。
- 不確かな点へfitを繰り返すことや、感度幅を都合よく広げて合格にすることは行わない。

## 次の最小手順（提案。まだ実施していない）

1. V字より大きい、白黒の領域が交互に接する基準を用意する。まずはA3程度の
   大きな2×2市松模様等を試し、4領域の中央交点を測距の対象点にする。
   A3は視認性確認の開始サイズという工学的提案で、検出成功や距離精度の保証ではない。
2. 平らな床へ置き、使用レンズ中心の真下から**中央交点まで**2.00mに合わせる。
   紙の手前の端や模様の外周を2.00mへ合わせない。板厚・反りがある物を床面点と混同しない。
3. 車体を静止させ、通常のカメラ・解像度・固定状態のライブ映像で、中央交点を
   特定できるかだけ先に確認する。見えない場合は配置一式を録画する前に見直す。
4. 見えることを確認してから、複数距離/左右の記録条件を固定する。今回はまだ録画一式を要求しない。

目的は床上の既知点と画像上の交点の対応を得ること。標準チェスボードの検出・
全面的な魚眼内部校正・ArUcoの姿勢推定を、この2×2模様だけで完了できるという意味ではない。
OpenCVの校正も既知の空間点と画像点の対応を使用し、標準チェスボードでは角点検出・
サブピクセル処理を行う：[OpenCV公式校正チュートリアル](https://docs.opencv.org/4.12.0/dc/dbb/tutorial_py_calibration.html)。
今回の高コントラスト交点の提案は、その対応を読み取りやすくするためのものである。

新しい基準でも画像が数画素へ潰れる場合があるため、全録画より先に2mの視認テストを行う。
色や模様の存在だけでなく、交点の位置を一意に選べることを確認する。
ハンコン・コーン・ロボット走行は、この視認性確認には不要。
実機をこちらから起動したり、FFBを許可する設定へ変えたりはしていない。
