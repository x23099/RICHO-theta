# コーン全高73 cmによる既知寸法測距（2026-10-21）

## 結論

ユーザーの実測回答「床から先端まで、台座を含めて73 cm」を使い、既存6,876フレームで比較した。**高さ基準は台座の見かけ幅基準より有望**。ただし、未校正のカメラモデルと画像端点の物理対応に矛盾が残るため、本番・FFBへの採用はまだ承認しない。

主案の高さproxyは8評価条件中7条件で事前の距離差目安を満たした。台座手前辺→先端軸の奥行き差18.75 cmを仮定した別案も7/8だが、未達の条件が異なる。条件ごとに良い方を選ぶ方式にはしていない。

## 実装した方法

主案 `colour_vertical_proxy`：既存の対象関連付け・色分割を維持し、ネイティブ1280×720の色輪郭の最上行を先端候補、そのXに最も近い実観測下包絡列を底候補にする。隠れた点を補間・外挿しない。この2点が実物の同じ鉛直軸に対応することは未確認である。

OpenCVの `fisheye.undistortPoints` で2点を仮想ピンホール座標に変換し、床基準軸へ回転した視線をr_tip、r_baseとして次式を最小二乗で解く。

```text
s_tip * r_tip - s_base * r_base = (0, 0, 0.73)
```

光学奥行きを両点で同じと決め打ちせず、既知の回転を用いてpitch/rollを扱う。床交点やカメラ高さで深度を決める方式ではない。カメラ高さは最後の原点平行移動に使うだけで、58→59 cmの変更で高さ方式の前方深度が改善したとは報告しない。

別案 `colour_near_edge_offset_assumption`：式の右辺を `(0.1875, 0, 0.73)` とする。先端が台座中心の上、選択した底点が軸平行台座の手前辺にあるという仮説。一辺37.5 cmの半分を使った物理仮定で、設置距離からfitした係数ではない。ただし台座yaw、左右位置、台座厚さと色境界の違いは未確認で、この差分を正しい補正と断定しない。

対照 `bbox_vertical_control`：保存YOLO枠の上下中央を主案と同じ式で処理する。枠端が物理的先端・底とは限らない。

固定済みの `recorded58` / `height_only59` / `paper_centre2` の3幾何を保存。主表は前回同様 `height_only59`。距離・寸法・姿勢・倍率は新しい設置距離に合わせて最適化していない。魚眼Kは従来の理想等距離仮定、D=0で、**新しい実測内部校正ではない**。また、この計算内の剛体変換は実TFノードの導入ではない。

モデル式と魚眼変換の参照：[OpenCV カメラモデル](https://docs.opencv.org/4.5.5/d9/d0c/group__calib3d.html)、[OpenCV 魚眼モデル](https://docs.opencv.org/4.5.5/db/d58/group__calib3d__fisheye.html)。この資料の2視線＋既知線分式は、それらの投影・剛体変換に基づく本試験の条件付き実装であり、先輩の実装を再現したとの意味ではない。

## なぜまだ本番にしないのか

**前方距離が近くても、3D位置全体は整合していない。** 底候補を床へ強制投影せず推定したところ、主案の床上高さ中央値は次のようになった。

| 条件 | 推定した底候補の高さ中央値（m） |
|---|---:|
| 静止中央0.80／1.30／2.00 | +0.044／+0.083／+0.130 |
| 静止左／右1.30 | +0.089／+0.075 |
| 同一姿勢系列1.30／2.00 | −0.013／−0.016 |
| 10/19 2.00 | +0.248 |

これらは実物の台座厚さを測定した値ではない。画素対応・原点/姿勢・内部モデルの不整合が残る診断値で、取付が変化したと断定していない。

また、仮定した既知線分と2視線の最小二乗残差は、主案で区間中央値約1.2～5.1 cm、奥行き差案で約1.6～7.2 cm。事前固定の残差2 cm以内フラグを満たさない区間があり、主案では静止右以外の7区間で該当フレーム0だった。距離だけの7/8成功を、物理的な点対応の7/8成功と解釈してはいけない。主表には残差の大きい推定も残している。

遮蔽で先端・底の見える縦幅が縮めば遠く推定し得ることを合成テストした。系列の遮蔽付近は[時系列グラフ](results_r01/height_occlusion_and_floor_residual.png)に残し、欠測を補間していない。正しい寸法でも、見えていない全高を見えている扱いにはできない。

## 検証・保存範囲

6,876フレーム×3幾何×3方法＝61,884行。10/15の既存YOLO枠と色輪郭を再利用し、10/19のみ既知ROIの赤色輪郭で処理した。新しいYOLO推論・学習は行っていない。全ネイティブ録画を再読込し、旧幅試験で使った色下包絡の左右端と完全一致することをフレームごとに照合した。対象なし・遷移・推定不能も保存した。

新規22テスト（既知縦線分の復元、pitch/roll/左右位置、奥行き差、寸法スケール、遮蔽、サブピクセル、無効入力、全フレーム、独立した生視線と解析式による全推定点再計算、同一フレーム比較、ハッシュ・集計再計算）を実施。旧幅試験17件と既存幾何24件も合わせ、**計63件成功、失敗・エラー0件**。[検証要約](verification_r01/summary.json)と[ログ](verification_r01/test_log.txt)へ保存済み。

統合テストの初回では、過去の複数の `analyze.py` が同じモジュール名で解決され、旧幅試験3件が実行エラーになった。検証ランナーで旧幅試験が元のモジュールを参照するよう明示して再検証した。推定式・入力・保存済み数値は変更していない。Matplotlibの未使用3D機能の警告は出るが、2Dグラフは保存・目視確認済み。

実TF・ROS・FFBの実機試験ではない。追加撮影、本番設定・モデル・GPU環境・ハンコン安全制限の変更、Git commit/pushはしていない。`calibrated_intrinsics=false`、`physical_endpoint_correspondence_verified=false`、`usable_for_ffb=false`を維持する。
