# 既知寸法＋ピンホール測距の既存録画検証（2026-10-21）

## 結論

既知寸法で深度を決める方式には検討価値がある。ただし、**台座の見かけの全幅を一辺37.5 cmと見なす今回の案は、本番採用を保留**する。8条件中5条件が事前の開発用目安を満たさなかった。これは既知寸法方式・ピンホール方式全体の否定ではなく、画像上の幅と物理寸法の対応に関する結果である。

10/19の設置距離2.00 mでは幅方式の中央値2.094 mとなり、同じ視線の床交点3.557 mより設置値に近づいた。一方、左右配置や別録画の2.00 mでは過小推定が残る。1区間で近い値が得られただけでは、校正・測距の完成とは判定しない。

先輩の実装コード・寸法対応点は不明であり、同一手法の再現とは呼ばない。新しい実測内部校正、solvePnP、実TF配信、本番設定・FFB変更は行っていない。

事前に固定した開発用目安は、各区間の中央値の差が±0.10 m以内、絶対差p95が0.20 m以内。FFBの正式な安全・精度要件ではない。閾値変更や距離に合わせた倍率調整はしていない。[判定JSON](results_r01/screen.json)

## 方式と前提

1. 保存済み対象関連付けと色下包絡から、可視成分の全幅の左右端点を取得。中央80%の支持幅を一辺として使わない。
2. OpenCV `fisheye.undistortPoints` で端点を仮想透視画像座標へ変換。仮想画像は960×960、FOV90°、fx=fy=480。
3. 仮想画像の横幅wに対し `Z_optical = fx × 0.375 / w` とする。両端が同じ光学Zにある正面向きの実辺、という仮定が必要。
4. 中点の光学3D座標を既存の剛体変換で床基準ROS軸へ変換。表の前方Zと光学Zを区別する。TFは座標変換であり、距離や焦点距離を自動的に校正するものではない。

魚眼のKは従来の理想等距離仮定、歪み係数D=0で、実測校正済みではない。実画像全体を変換・保存せず、座標のみを変換した。既知寸法法を適用するためにも、魚眼の生画素幅をそのままピンホール式に入れないことが重要となる。

固定幾何 `recorded58` / `height_only59` / `paper_centre2` を併記したが、今回の距離で最適化・選び直しはしていない。カメラ高さ58→59 cmの変更で幅方式の前方Zは変化しないこともテストした。10/19の2 mは順に2.094／2.094／2.073 m。

検出bboxの左右下角を使う対照も保存した。こちらは物理的な幅の対応がさらに弱く、置換だけで全条件を満たさない。例えば静止中央2 mは1.750 m、左は0.936 m、右は1.078 mとなった。

参考：[OpenCV カメラモデル](https://docs.opencv.org/4.5.5/d9/d0c/group__calib3d.html)、[魚眼モデル](https://docs.opencv.org/4.5.5/db/d58/group__calib3d__fisheye.html)、[既知3D点対応によるsolvePnP](https://docs.opencv.org/4.5.5/d5/d1f/calib3d_solvePnP.html)。今回は台座四隅の確実な3D–2D対応を用意できていないため、架空の四隅を作ってsolvePnPを実行していない。

## 残る問題の切り分け

- **台座の向き・支持範囲**：正方形の見かけの全幅は、必ずしも一辺ではない。斜めに見えると複数の辺を含み、両端の奥行きも異なり得る。理想ピンホールによる独立の合成試験では、近側辺を1.30 mに固定してyawを0／15／30／45°と変えるだけで、推定は1.300／1.240／1.137／1.107 mになった。実録画のyawを測定した結果ではなく、実誤差をこれだけで説明するものでもない。
- **遮蔽**：見える幅が狭くなると反対に遠く推定する。系列録画ではフレーム1133で約4.35 mとなる外れ値も残した。範囲外を切り詰めたり削除したりしていない。従来の支持範囲品質ゲートによる副集計も保存しているが、復帰後にも安定した過小推定が残り、遮蔽除去だけでは解決しない。
- **床との整合性**：幅から復元した点を床へ強制投影していない。台座と見なした点の推定高さ中央値は区間により床上約7.6～25.3 cm。これは実台座の高さを測定した結果ではなく、幅対応・画素位置・カメラモデル・基準点の不整合を示す診断値。前方距離が近くても、この矛盾は残る。
- **原因の限界**：実際の台座yaw、端点の物理対応、画素量子化・影、内部校正の影響を今回だけで一意に分離していない。取付変化を原因と断定していない。

## データ・確認範囲

既存10/15の5,143フレームと10/19の1,733フレーム、計6,876フレーム。3幾何×2幅方式の全41,256行を保存。対象なし・遷移・推定不能も削除していない。10/19は以前に固定したROI内の赤色成分であり、新しいYOLO推論結果ではない。

独立した座標再計算、既知寸法の合成投影、遮蔽・yaw感度、距離範囲外の保持、全フレーム保存、参照距離による推定非依存、入力ハッシュ、既存幾何との整合性など、**41テスト成功**。実機ROS・ハンコン試験、GPU推論試験ではない。結果は `calibrated_intrinsics=false`、`physical_width_correspondence_verified=false`、`usable_for_ffb=false` を維持する。

解析の初回実行で既存クラスの必須引数 `front_lens` が不足して停止したため、左レンズを明示して再実行した。数値出力前のエラーであり、未完了結果は採用していない。Matplotlibの未使用3D機能の警告は出たが、2Dグラフを保存・目視確認済み。

## 次の最小の確認

追記：同日ユーザーから全高**73 cm**の実測回答を得たため、[高さ方式の独立した検証](../cone_known_height_pinhole_r01/README.md)を実施済み。以下は幅試験終了時点の次の確認事項として残す。幅試験の入力・数値結果は変更していない。

**床からコーン先端までの全高（台座を含む実測cm）**が分かれば、正方形台座のyawに左右されにくい縦寸法を使う候補を既存録画で比較する。今回確認できた実寸は台座一辺37.5 cmのみで、全高を画像・設置距離から逆算して真値の代用にはしない。

追加録画は現時点で依頼しない。高さ方式でも姿勢・魚眼モデル・遮蔽への検証は必要で、精度改善を保証するものではない。内部校正の必要性は、寸法対応を改善した後の結果とも分けて判断する。
