# 近接自己遮蔽の表示保留

## 範囲

現行の主測距・元ログ・別比較は保持する。新しい明示opt-inの表示専用ゲートを追加し、
現在の主支持列を、同接続でpin/load照合済みの境界へ当てて保留のみを行う。
別比較の数値を主表示へ採用せず、half-pixel救済も導入しない。距離式・検出閾値・平滑化は変更しない。
操縦・ROS・FFB・カメラ送信経路は変更しない。既定OFF時は既存のIPC・表示挙動を維持する。

## 設計

1. 比較workerの単一ownerが成功したactivateからだけ、小さい境界参照コピーを公開する。
   参照未読込み・要求処理・失敗・失効・session変更・終了ではコピーを使用不可にする。
   主測距側の取得はnonblocking lockであり、ロック待ちやUIからのファイル読込みを追加しない。
2. GPU子プロセスで同じフレームの元support_observationに既存のcompare_self_bodyを適用する。
   元距離・元主ログは変更せず、表示レビューを別ログとIPCの小さい任意フィールドへ記録する。
3. UI bridgeはレビューのsession/frame/source時刻・元数値一致を検証し、元の値を保つかWITHHELDにする。
   レビューが欠落・不正・古い場合はOFFへ黙って戻さず、表示を保留する。
4. 入力の空白・参照generation・activation以降の未来フレーム条件を守る。
   原画像の変更・過去フレームへの参照の遡及適用を実機成功と扱わない。

## 検証

合成データで境界接触・支持範囲外・参照なし・失効・ロック競合・session変更・古い入力・不正IPC・元数値不変を検証。
既存r02の主support_observationから表示保留をオフライン再計算し、録画区間と前試走を分離する。
録画内の267自己遮蔽件を保留し、比較許可の911数値は同値、元保留8件は解除しないことを確認する。
既存のbridge・比較・証拠保存・操縦AST不変テストを実行する。実カメラ/GPUの再確認は未実施と明記する。
