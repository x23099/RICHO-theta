正常終了時に最後の1件が未処理でも、offeredとprocessedの不一致だけで障害とはしない。元のログ・statusを保持し、主処理や参照の状態を捏造しない。停止により古いsessionを再開できないことと、提出画像の妥当性は別問題である。

## 今回画像の境界と取付の条件

[reviewed_boundary.csv](reviewed_boundary.csv) は今回のnative画像を見て読んだ局所境界。x=270〜380だけを扱い、範囲外へ外挿しない。床→黒い天板の明暗段差を画素値でも確認し、椅子の脚などの別の段差を除外した。黄色テープで境界の明暗が弱いx=326〜349は直接読めた隣接点間の補間になる。読取りの目安は約2pxで、物理距離の誤差保証・統計的信頼区間ではない。

今回の天板上端は中央付近y=447、11/10の参照はy=458付近で、約10〜11px上に見える。この画像差だけからcamera pitchや高さの変化量を断定しない。**ユーザー回答：カメラの電源操作のため毎回取り外しており、基本の取付場所は同じだが完全一致とは言えない。** 今後、録画間の取付姿勢・高さを検証済みとして扱わない。

今回の境界読取りは自己領域の棄却用で、床法線・カメラ外部姿勢・高さを校正する情報ではない。同じ場所に付けたことや天板から離れた支持点を見たことだけで距離精度・床接地を認定しない。既存の床profileによる距離は取付仮定を含む未検証の診断値として扱い、走行／制御への採用判断とは分ける。現時点で再校正一式・新規床マーカー撮影を要求しない。

このCSVは終了済み画像の分析記録であり、load用reference.jsonを生成したものではない。次のpin画像でも現在の境界を確認してから、その新session／frame／PNG SHAに対応する参照を作る。古いJSONのsessionだけを書き換えて渡さない。

## 受信を止めずに提出するには

pinで作ったPNGと同名JSONは、その後の映像更新では書き換わらない。更新を続けるのは比較ログとstatus。フォルダ全体を圧縮せず、**PNG・同名JSON・statusの3点をいったん別フォルダへコピーしてから、そのコピーを圧縮する。** コピーされたstatusはその時点のスナップショットとなる。`comparison_frames.jsonl`と`request.json`は今回の途中提出には不要。

再開後は主保存先・比較保存先とも新しいr02へ変更する。同じ接続のままpin→提出→こちらで現在境界参照を準備→loadへ進む。接続が切れた場合や失効が報告された場合は知らせる。load前の主数値206行だけから精度や保留原因を判定せず、load後の主／比較全ログは終了後にまとめて監査する。
