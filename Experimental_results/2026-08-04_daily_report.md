# 2026年8月4日 実装・実験レポート

## 1. 本日の目的

RICOH THETAによる鳥瞰表示を、白線の可視化段階から障害物の位置推定段階へ進めるため、以下を実施した。

- 実測したカメラ設置高さへの更新
- 鳥瞰変換の姿勢・レンズ・空間スケール調整
- 実験映像を再利用できる録画機能の追加
- 青色段ボール箱を評価用障害物とした検出処理の実装
- 既知位置6地点を使った位置推定精度の評価
- 実験データと集計結果の保存方針整理

- 車体幅・全長：0.354 m

## 3. 実装内容

### 3.1 カメラ高さと鳥瞰投影の再調整

カメラ高さを従来の約40 cmから実測58 cmへ更新した。初期値、リセット値、Kobukiプロファイル、モックカメラ、画面説明、設定ファイルを0.58 mへ統一した。

実映像を確認しながらYaw、Roll、Pitch、レンズ中心、空間スケールなどを調整した。調整後は以下を確認済みである。

- 停止中に白線と車体中心がほぼ平行
- 直進時に地図が不要に回転しない
- 後退時に地図が逆方向へ移動する
- 左右旋回時に地図が正しい方向へ回転する
- 前進・後退後の位置ずれが大きくない

### 3.2 録画機能

`bird_eye.py`の鳥瞰画面下部へ録画開始・停止ボタンを追加した。

1回の録画で以下を同じセッションフォルダへ保存する。

| ファイル | 内容 |
|---|---|
| `raw.avi` | THETAの元デュアル魚眼映像 |
| `bev.avi` | 鳥瞰変換・車体表示を含む映像 |
| `detection.avi` | 白線検出・占有地図・障害物検出映像 |
| `metadata.json` | 撮影時の入力・投影・検出設定 |
| `detections.csv` | フレームごとの青色障害物推定座標 |

録画中は経過時間を表示する。停止ボタンまたはウィンドウ終了時にVideoWriterとCSVを閉じ、動画破損を防ぐ。

### 3.3 青色障害物検出

以下の処理を追加した。

1. BEV画像をHSV色空間へ変換
2. 青色範囲を二値抽出
3. モルフォロジー処理による小ノイズ除去と領域補完
4. 面積しきい値以上の最大輪郭を障害物として選択
5. 輪郭上で車体中心に近い点群の中央値を接地点とする
6. BEV画素を車体基準座標 `(x, z)` と距離へ変換
7. 輪郭、接地点、座標、距離を鳥瞰・検出画面へ表示

検出は画面の `Detect blue obstacle` で有効・無効を切り替えられる。

### 3.4 オフライン評価機能

`src/evaluate_blue_obstacle.py`を追加した。セッション名から正解座標を読み取り、`raw.avi`をカメラ高0.58 mで再投影して、複数フレームの中央値と位置誤差をCSVへ出力する。

実行例：

```bash
python3 src/evaluate_blue_obstacle.py /path/to/recordings \
  --camera-height 0.58 \
  --output Experimental_results/blue_obstacle_evaluation.csv
```

## 4. 実験方法

車体を固定し、青色段ボール箱を以下の6地点へ配置した。`x`は車体左右方向、`z`は車体前方距離である。

- `(x, z) = (-0.5, 1.0) m`
- `(x, z) = (+0.5, 1.0) m`
- `(x, z) = (0.0, 0.5) m`
- `(x, z) = (0.0, 1.0) m`
- `(x, z) = (0.0, 1.5) m`
- `(x, z) = (0.0, 2.0) m`

各地点で約4.6～4.8秒を録画した。全セッションについて、元映像・鳥瞰映像・検出映像が正常に読み出せ、同一セッション内のフレーム数も一致した。

## 5. 実験結果

| 正解位置 `(x, z)` m | 推定位置 `(x, z)` m | 位置誤差 | 検出率 |
|---|---|---:|---:|
| (-0.5, 1.0) | (-0.416, 1.010) | 8.5 cm | 100% |
| (+0.5, 1.0) | (+0.688, 1.048) | 19.4 cm | 100% |
| (0.0, 0.5) | (+0.136, 0.768) | 30.1 cm | 100% |
| (0.0, 1.0) | (+0.068, 1.048) | 8.3 cm | 100% |
| (0.0, 1.5) | (+0.072, 1.512) | 7.3 cm | 100% |
| (0.0, 2.0) | (+0.108, 2.016) | 10.9 cm | 100% |

- 6地点すべての検出率：100%
- 全地点の平均位置誤差：14.1 cm
- 1.0～2.0 m範囲の平均位置誤差：約10.9 cm
- カメラ高0.50 mで再処理した場合の平均位置誤差：16.3 cm

詳細値は `Experimental_results/blue_obstacle_evaluation.csv` を参照する。

## 6. 考察

### 良好だった点

- 青色段ボール箱は全評価フレームで検出できた。
- 正面1.0～2.0 mでは、前後方向誤差は概ね1～5 cmに収まった。
- カメラ高は調整値0.50 mより、実測値0.58 mを用いた方が全体精度が良かった。
- 元映像を同時保存したことで、再撮影せずに投影条件を変更して再評価できた。

### 課題

- 0.5 m地点は車体直近の死角と立体物の床面投影歪みの影響が大きく、約30 cmの誤差が出た。
- 推定値に全体的な右方向への偏りがある。
- 右側0.5 m地点の横方向誤差が約18.8 cmあり、左右対称性が十分ではない。
- 現在の色検出は評価用の青色箱専用であり、一般障害物認識ではない。
- 録画時のメタデータは0.50 mだったが、元映像を実測0.58 mとして再処理して評価した。今後の録画では最初から0.58 mで保存する。

## 7. データ管理方針

- `recordings/`：元動画、処理動画、セッションメタデータ、フレーム別ログを保存するローカル領域。Gitでは追跡しない。
- `Experimental_results/`：集計CSV、グラフ、代表画像、日次レポートなど、共有可能な実験結果を保存する。
- 大容量動画はGitへ追加せず、必要に応じて外部ストレージまたはPC間転送で共有する。
