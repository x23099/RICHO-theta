## 0. 用語の説明（先に読んでください）

| 用語 | 意味 |
|---|---|
| **青箱** | 走行中に障害物として認識する青い箱。距離・危険度・制動の判断材料になる |
| **FFB（緊急制動）** | 危険と判断した時、ロボットが即座にブレーキをかける機能 |
| **完全遮蔽** | 障害物の映像が完全にカメラから消える状態（箱が壁の後ろなどに完全に隠れる） |
| **UNKNOWN** | 「障害物が見えない／判断できない」状態。見えている障害物と区別して通知する |
| **dry_run（ドライラン）** | 実際にブレーキを動かさず、記録データだけを流して「指令を出すか」を確認する検証 |
| **mock ODOM** | 実走行の代わりに、実験用のダミー速度を入力して動作を再現すること |
| **コーン** | 走路の障害物として扱う三角コーン（赤・黄の2色） |
| **YOLO** | 画像の中から物体の位置を検出するAI。位置を四角い枠（bbox）で返す |
| **学習（訓練）** | AIに例を示して、「この画像には、この位置にコーンがある」ことを覚えさせる作業 |
| **epoch** | 学習データを1回すべて通して習う回数。50回なら、同じ内容を50回分反復して習うこと |
| **Precision** | AIが出した検出のうち、正しいものの割合 |
| **Recall** | 正解の物体のうち、AIが見つけられた割合 |
| **mAP50** | Precision と Recall をいくつかの閾値について平均した総合指標（1に近いほど良い） |
| **confidence（信頼度）** | AIが「これはコーンだ」とどれだけ確信しているかのスコア（0〜1） |
| **閾値（しきい値）** | この値より信頼度が高ければ「見つけた」とする線。0.25なら0.25以上の検出だけを採用する |
| **クラス（category）** | AIが物の「種類」を表す区分。今回は赤と黄をまとめて1種類「コーン」としている |
| **bbox下端** | 検出枠の下側のピクセル位置。「床の接地点」になり得るという前提で距離計算に使われることがあるが、この期間はその前提を確認していない |
| **魚眼（dual-fisheye）** | 前後2つのレンズで広い範囲を映すカメラ。周辺が曲がって写るため距離計算が難しくなる |
| **独立test（独立テスト）** | 学習に使っていないデータで評価すること。開発用のデータで得た数字はこれに当たらない |

## 2. できたこと

### 2-1. 10/07: 青箱の「消えた時 → 戻った時」の通知確認

やったこと: 箱を壁で完全に隠す実験を3回行い、Kobuki（走行するロボットのPC）と操縦するPCの間でメッセージがどう伝わったかを記録し、1件ずつ照合した。

| 項目 | 結果 |
|---|---|
| 完全に隠れた区間 | 2回目・3回目で各2区間（1回目は箱の上端が見えており「部分的に隠れた」ため対象外とした） |
| 通知の判断（合計114回） | 114回すべて「指示が正しく届き、正しく返答」 |
| 途中で撤回・拒否された回数 | 0回 |
| 通知の出し方 | 隠れている間は1回だけ（連打しない）／再び見えると3回連続で警告 |

**副成果（改良案の明文化）**: 通信の「古さのチェック」と「通信が切れた判定」を分けた。
- 従来: どちらも60 ms基準 → 一瞬の通信の乱れでも1秒待ち直すことになる
- 改良: メッセージの鮮度は60 msのまま、**切断の判定だけ200 msに緩和** → 通信が一瞬乱れても、1秒待たずに復帰できる

### 2-2. 10/12: コーンAIの第一步（材料づくり → はじめての学習）

| 項目 | 結果 |
|---|---|
| 用意した録画 | 4本、合計11,916フレーム |
| 学習用の画像 | 205枚 |
| 学習に使わない評価用の画像 | 195枚 |
| まず最初に人が確認した分 | 73枚 / 枠109個 |
| 人の目視確認 | 73枚すべて確認済み |
| 学習 | 50回（1分16秒） |

学習後の評価結果（学習に使っていない画像での検証）:

| 指標 | 値 |
|---|---|
| Precision（出したものが正しい率） | 93.8% |
| **Recall（正解を見つけられた率）** | **64.3%** |
| mAP50（総合） | 94.1% |

この段階での判断: Precision は高いが **Recall だけが低い**。「見理科が限られる」という課題が判明。ここから10/13の診断が始まる。

副成果: 「赤いコーンがない録画」の後ろにも**黄色のコーン**が映っていたため、黄色もコーンとして学習対象に入れた（赤だけを専門に認識するモデルではない）。

### 2-3. 10/13: コーンAIの弱点を特定（本期間最大の成果）

#### a) Recall 64.3% の正体は何だったのか

AIが「見つけられなかった38個」を1個ずつ人の目で確認したところ:

| 閾値 | 赤いコーンの見つけ率 | 黄色のコーンの見つけ率 |
|---|---:|---:|
| 0.25 / 0.50 | **18個中18個 = 100%** | 0個中38個 = 0% |
| 0.10 | 100% | 10.5% |
| 0.05 | 100% | 94.7% |

> **つまり「Recall 64.3%」は赤いコーンの性能でしたくなかった。黄色のコーンが1個も検出されず、数字を押し下げていた。**
> **赤いコーンだけを見ると、閾値0.25で18個中18個（100%）です。**

- 黄色が弱い理由の候補（未確定）: 学習に使う黄色のコーンは小さく（高さ24〜44 px）、評価に使う黄色は約140 pxと大きさがまったく違っていた。
- 閾値0.05での「黄色方面的誤検出7件」の内容も確認した。うち3件は「赤いコーンを二重に示しただけ」、1件は「赤と黄が両方入った広い枠」、3件は「コーンではないもの（人の手・衣服など）」。**「背景を7回見誤った」わけではない。**
- 閾値0.05でも見逃した2件は、AIの候補自体は存在しており、「0.05というしきい値で捨てられた」だけだった。

#### b) 止まった写真だけでは通らないことを実証

走行を模した動画2本（合計**5,808フレーム、1フレームも飛ばずに**全フレームを評価）:

| 項目 | 赤いコーンを動かす動画 | 赤いコーンが無い動画 |
|---|---:|---:|
| 総フレーム数 | 5,236 | 572 |
| 何かを検出できたフレーム | 5,188（99.1%） | 0 |
| 1件も検出できなかったフレーム | 48フレーム（10か所） | 572（全編） |

- 99.1%という数字は**「正解率」ではない**（この動画には正解の枠が決められておらず、単に「何か検出できたフレームの割合」）。
- **検出できなかった10か所から、各1枚（計12枚）を人が確認** → 10か所中8か所で、赤いコーンの本体が少なくとも一部は写っていた。
- さらに**その12枚だけ閾値を0.25から0.01まで下げて再判定** → 10か所中9か所で「赤いコーンと重なる候補」が見つかっていた（スコア0.146〜0.247）。

つまり「映っているのに見つからなかった」のではなく、**「手持ちで運んでいる・傾けて持っている・カメラの端で一部が欠けていたため、AIの確信度が低くなっていた」**のが原因と推測される。

#### c) 距離測定に使う前の重要な発見

AIが描いた枠の下端が、**コーンを手で持っている状態では床に触れていない**ため、「枠の下端＝床との距離」と単純に扱うことはできないと判明した。
- 実際に、AIの枠の下端が33ミリ秒のあいだに**28ピクセル（大幅）** 急に変わる場面があった。コーンがカメラの境界をまたいだ瞬間に、枠が別の形状に切り替わっていたため。

#### d) 次の学習に使う画像の準備

- 学習用にまだラベル付けしていない170枚をAIにかけると、確認用の候補が819個出た。
- **「候補が0個だった画像」は0枚** = 学習用の170枚のうち、閾値0.25以上で1件も検出できなかった画像はなかった。ただし赤コーンに限った話ではなく、赤と黄をまとめたクラスでの結果である。
- そのうち**人が確認すべき16枚を選抜して用意**した。**AIの予測を正解として自動登録する処理は止めてある**（人の目視確認を必ず挟む設計）。

## 3. できなかったこと（残課題）

### 3-1. 青箱（10/07時点から継続）

- **ある1条件だけ距離が約8 cmずれる件（1.10 mの位置）の原因がまだ特定できていない。**
  - 校正値・カメラ的几何・左右方向・過去データの4経路から調べたが、特定できず。
  - 「今回の1条件の値に合わせて補正を入れる」ことは**していない**（他の条件で精度が壊れる恐れがあるため）。
- ブレーキ試験はすべて**計算上（ドライラン）**。**実車でブレーキが実際に出た回数を検証したわけではない。**
- 通信が一瞬切れて再安定化する場面は観測したが、原因（ネットワーク・演算・CPU負荷のどれ）が未特定。

### 3-2. コーンAI

- **学習に使っていないデータでの評価（独立テスト）が存在しない。** 上記の数字はすべて開発用のデータでの値。
- **コーンが1個も無い場面の画像が1枚も無い。** 誤検出（誤ったものをコーンと認めてしまう）が起きうる範囲は評価できていない。
- **黄色のコーンの精度向上は未着手。**
- **コーン検出 → 距離 → 危険度 → ブレーキ の接続は実装していない。** 現時点では接続しない判断を取っている。
- **白線の逸脱（線の外へ出る）検出は未着手。** 左右どちらを境界とするかの合意が先。
- 10/13の推論は**手持ちの静止画と動画のみ**。実カメラ・実車での動作確認は取っていない。

### 3-3. 環境・運用

- **GPU環境**: 学習は一台のPC、推論・診断は別のPCで実施している（**意図的な分離**。ただし両者の数値差の影響は今後確認が必要）。
- 学習時にGPUエラー（CUDA unknown error）が発生したが、**PC再起動で解消**。根本原因は未特定。
- 10/08〜10/11は作業記録なし。
- 10/13の成果物は**未コミット**、日報も未作成。

## 4. 発表時の注意（この数字の読み方）

1. **「Recall 64.3%」と「Recall 100%」は条件が違う。** 後者は止まった写真38枚・閾値0.25・学習用でない仅仅是開発用のデータでの値。未知の環境・動画・実車ではない。
2. **「検出できたフレーム 99.1%」はRecallではない。** 正解データが無い動画における検出率。
3. **「候補が見えた」は「枠が正しい・床に接地している・距離に使える」を意味しない。**
4. **処理時間 p95 25 ms は、画像処理だけのオフライン値。** 実カメラ・通信・制御を含めたフレームレートの保証ではない。
5. **10/07の通知確認は計算上のみ。** ブレーキが実際に制御された回数の検証ではない。
6. **黄色と赤は同一のカテゴリで学習している。** 「赤だけを認識するモデル」ではない。

## 5. 次の予定

1. **追加学習**: 用意済みの16枚を人が確認してラベル付け → 学習データに追加 → 再学習 → 前回と同じ条件で比較。
2. **黄色の対策**: 大きさ・背景・置き場所を変えたデータが必要かを、現在の結果から判断する（先に大量撮影はしない）。
3. **距離との接続**: 「床に置かれたコーンで、AIの枠の下端を距離に使える条件」を切り分け。ここが解けるまでブレーキには接続しない。
4. **独立テスト・コーン1つも無い場面・未使用の背景での評価**を確保する。
5. **白線逸脱**は、左右どちらを境界とするかの合意から着手。
6. **事務**: 10/13成果物のコミットと日報作成、GPU環境問題（CUDA原因不明）の整理。
